# 视频制作标准（以第01、02篇为定稿样板）

> **开工前必读：[`硬性条件.md`](硬性条件.md)（所有硬性条件汇总，音频质量最高优先级）和 `踩坑总表.md`。**

> ⚠️ **开工前必读 [`踩坑总表.md`](踩坑总表.md)**（所有出过的问题及防范方法）；交付前运行 `python3 视频/工具/check_all.py NN`，并按总表末尾的检查单逐项确认。


所有70篇视频一律按本标准制作。参数已写死在 `工具/` 下的脚本里。

## 一、画面
- 16:9，30fps。**修改阶段出 1080p 草稿；定稿时出 4K（3840×2160）**：`VIDEO_S=2 python3 make_video.py …`（所有尺寸×2，排版完全一致），H.264 crf16；背景深绿渐变（上 #0E241E → 下 #143028）。
- **一句话一屏**；一句按意群拆成上/中/下几行（chunk），跟读高亮：正在读的行亮，其余行变暗。
- **逐词对照**：每个英文词/词组正下方放它的中文；能逐词对准就对准，硬对会让中文别扭时就合并成一组。中文从左到右连起来读，必须是一句通顺精准的整句。
- 手动换行：在 align 里插入 `["\n",""]` 强制换行（如 "In fairness," 单独一行、"and Wheeler" 单独一行）。
- **【用户定的规则】换行必须经用户同意**：不得擅自加换行、改换行、删换行，也不得为了排版自己选断行点（包括英文超宽时在哪里折行）。已经给用户看过的换行一律保持；要动必须先问。改完后用"逐句比对换行"检查（与用户上次看到的版本比，只允许用户要求改的句子有变化）。
- 中文格内换行：中文里写 `\n`，第二行起居中排在第一行正下方（如 set in → 也**出现了** / （不好的事到来且持续）。）。只按用户的要求用。
- 一格保持一行：英文开头加 `{{=}}`，这一格超宽时不自动折行，改为缩小这一屏的字号放下（第03篇第10句按用户截图保持一行，这屏字号 54）。
- 说明文字用重点词颜色：中文里写 `{{（说明）|english}}`，显示成该重点词的颜色，但不算重点词、不进速查表（第03篇第10句两个括号说明分别用 unimpressed 黄、assessors 蓝）。
- **字号**：保持既定换行不变，每一屏把字放到最大铺满屏幕（宽 ≤1860、高 ≤1020），上限 100 号；中文字号 = 英文 × 0.72。
- 中文数字/英文（如 1999）不拆行。
- 正文页**不显示**顶部标题。
- 重点词：英文与中文**同色**，按首次出现顺序循环 8 色调色板；重点短语整体上色（rubbed on、devoid of、calls for…）；**被隔开的短语两部分同色**（`**depends** partly **on**` ↔ `**取决于**(depends on)`）。
- 重点词中文两侧留约 1/4 字宽小间隙（标点旁、格子边缘不加）。
- 括号说明 `note`：单独一行放在该行译文正下方，浅灰绿；"另译"用**黄字**（note 以 `#Y` 开头）。

## 一（补）、英文标点修正：牛津逗号（2026-10-05 用户定）

- 这是对文章原文的修正，视频脚本、文章英文同时改；中文不受影响（中文"和"前不加顿号）。
- 已改：第01篇 grammar, and；第03篇 spicy food, and。以后每篇做视频前先查一遍。
- **【硬性标准】凡是能用牛津逗号的地方一律用**，这是今后每支视频、每篇文章的检查项。
- **停顿**：牛津逗号列举（A, B, and C / A, B, or C）里的逗号只停 **0.2 秒**（列举读得紧凑）；普通逗号 **0.4 秒**（2026-10-05 用户定）。`make_video.py` 自动识别列举（P_LIST=0.2，P_COMMA=0.4）。

## 二、标题页
- 全部居中。**视频里一律不写篇号**（2026-10-05 用户定：去掉顶部"考研英语精读 · No.XX"小标签和右下角篇号水印）。
- **品牌标志「朋克英语」只出现在片头标题页**，正文页、片尾等其他地方一律不出现。
- 标志样式（2026-10-05 用户从 5 版中选定 **E 拼字版**，设计过程见 `片头设计/README.md`）：70 年代朋克海报的"勒索信"拼贴。四个字各剪在一块不同颜色的撕边纸片上：朋＝黑底白字，克＝荧光粉底（站酷庆科黄油体），英＝米白纸毛笔字（马善政体），语＝亮黄底。纸片微微倾斜，角上贴米色纸胶带，下方有一条黑色打标签机胶条，印着"PUNK ENGLISH"。整个标志居中放在中文标题黄色色块正下方，比标题和色块小，不抢主角。程序为 `工具/title2.py`（随机纹理固定种子，每支视频完全一样）。片头约 1.5 秒入场动画（`工具/title_anim.py`）：英文逐行浮现 → 中文色块弹出 → 朋克英语纸片逐张贴上 → 胶带、PUNK ENGLISH 标签条；之后静止到片头结束。
- 英文标题超粗体、尽量大（最多 3 行），暖白色。
- 每篇挑最有画面感的词做特效（`title_fx`）：`hl` = 柠檬黄→橙渐变+发光；`ghost` = 从左到右渐隐、碎成光点。
- 中文标题：明黄色圆角长方形色块（小圆角，非胶囊形），深色超粗体，文字在色块内上下左右居中。
- 背景：中央柔光（不再有篇号水印）。

## 三、声音（2026-10-05 定为 F 方案 = B 原声 + 轻降噪）
- 男声美音：Kokoro `am_michael` 75% + `am_fenrir` 25% 混合（voice_mb.npy），语速 0.95。（旧版 voice_mf.npy 为 50/50、0.92，偏沙哑，已弃用）
- 后期（AF.txt）：高通 70Hz；**轻降噪 afftdn=nf=-40:nr=4 去沙哑颗粒感（2026-10-05 F 方案，其余不变）**；4800/9600 Hz 陷波去电流声；180Hz +1.5dB（饱满）、3000Hz +1.5dB（清亮）；低通 11kHz；soxr 升采样到 48kHz。
- 视频音频 AAC 256k。句尾只去极短低能量杂点，不切 s/z 尾音。

## 四、停顿
| 位置 | 时长 |
|---|---|
| 片头静音 | 0.4 秒 |
| 标题读完 → 正文 | **1 秒**：读完停 0.6 秒 → 切到第一屏 → 静止 0.4 秒开读（2026-10-05 用户定） |
| 标点处（, ; :） | **0.4 秒**（2026-10-05 由 0.6 改为 0.4）；牛津逗号列举内部的逗号 **0.2 秒** |
| 行与行之间（无标点） | 不停顿，整句连贯朗读 |
| 合成方式 | **整句一次合成**，逗号处只把模型自然停顿换成标准时长（2026-10-05 起；分段合成会让逗号后开头发闷） |
| 句号：读完静止 → 切下一屏 → 静止 → 开读 | **0.7 + 0.3 = 1.0 秒** |
| 段与段之间 | **共 1.2 秒**：读完 0.7 秒 → 换屏 → 0.5 秒开读（2026-10-05 用户定） |
| 片尾（最后一句读完后） | **2 秒** |

## 五、翻译标准
- 精准、地道、通顺三原则；不得添加原文没有的信息（需要补充的放括号）。
- 重点词中文**词性必须与英文一致**：形容词"……的"、副词"……地"、名词译名词、动词译动词；方向词（before/after 等）逐个核对。
- **先写一句通顺精准的整句，再往英文上对**：能逐词对就对，语序相反（比较/倍数结构 half as…as、介词短语后置等）就合并成一组，中文从上到下连读必须通顺。
- **用户亲自给出的译法一律优先，原样采用**（只统一全角括号）。用户给的说明性括号（如"为了（完成）""关于（考察了）"）照放。
- 括号说明 note：放在该行译文正下方；需要解释"什么和什么之间的关系"、数字含义（如 100% → 约 33%）时写清楚，数字要算对。
- 重点词增减：用户点名的词加为重点词；**新加的词若在其他篇加粗过（含同根、含短语中的实词）一律不加并提醒用户**，用户坚持保留的写入 `allow_clash`。

## 十、每篇制作流程（严格按此执行；最高铁律见 `硬性条件.md` 第〇节）
1. 读 `硬性条件.md`、`踩坑总表.md`、`翻译风格.md`、`音频事故复盘.md` 与本标准；运行 `交付核查.py NN 对照表` 生成"踩坑对照记录"模板，在 `制作记录/NN.md` 逐条填写。任何交付前都要过 `踩坑核查.py`（发文本前、出视频前自动调用；其他事用 `踩坑核查.py 通用`）。
2. 生成逐词对照初稿 `脚本/NN.json`（按第01、02篇样式），运行 `check_all.py NN`。
3. 译文先经独立审校（按 `翻译风格.md` 与踩坑总表逐条审），再用 `生成文本.py NN` 生成 Word / HTML / PDF（自动先过踩坑核查，生成后自动核对并拷进 `对照文本/`，不手敲命令）发给用户人工修正；用户发回后用 `read_docx2.py` 读回，只写回用户改动处。
4. 用户逐句提的修改：改 json（按整个 chunk 改，改完打印整句核对）→ 生成 **1080p 草稿视频**、Word、HTML、PDF → `sync_article.py` 同步文章与速查表 → `build_html.py` 重建合集 → **新加的重点词查撞词后写入词库 `词库/used_words.json`，并更新 `70篇重点词汇.xlsx`（`词库/build_xlsx.py`）** → `check_all.py` → 推送两个仓库。
   出片前后必须运行 `交付核查.py NN 出片前` / `交付核查.py NN 出片后`，都显示"全部通过"才能推送、发给用户（出片后含核查程序自检：故意造 5 处瑕疵必须全部抓到）。
5. 用户确认定稿后：`VIDEO_S=2` 出 **4K 定稿视频**（同样先过《交付核查》），推送并从云端核对。
6. 本篇新踩的坑立即追加到 `踩坑总表.md`，修改过程记入 `制作记录/NN.md`。
