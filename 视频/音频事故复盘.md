## 二、根本原因（不是运气不好，是做法错了）
1. **自己检查自己**：核对程序与出片程序由同一人、按同一套假设写成（例如都用"单个采样峰值"做响度基准），盲点完全相同，所以核对"全部通过"而问题仍在。换成**独立方法**（与原始合成逐样本比对）后问题立刻暴露。
2. **改一处，只验一处**：配音处理连续改了四次（分段合成 → 整句合成 → 估算停顿位置 → 精确定位停顿），每次只验证当时要修的问题，没有对所有方面做**整体回归**，新问题在修旧问题时被引入。
3. **门槛靠估计，没有阳性对照**：判断"听不见"的门槛没有用"故意剪坏的音频"测试过能不能抓到问题。独立检查员用剪掉 25 ms /f/ 的样本验证了自己的程序，才可信。
4. **默认模型读得对**：没有列出数字、日期、缩写逐个核对读法。
5. **先交付、后核查**：有几次先发给用户、先推送，后核查；还推送过一次生成失败的产物。

## 三、对应的永久措施
| 原因 | 措施（已写入《硬性条件》第零、六节） |
|---|---|
| 自己检查自己 | 出片后必须由**独立方法**复核（`工具/独立复核/`：与原始合成逐样本比对），词尾/词头被切 = 0、多余声音 = 0 |
| 改一处只验一处 | 配音处理程序**任何改动**后，已出片的所有篇目必须全部重跑《交付核查》，全部通过才算改完 |
| 门槛没验证 | 《交付核查》出片后先做**核查程序自检**：在成片音频副本上故意造 5 处瑕疵（词尾、词头各轻切一处、重切一处，加一处杂音），复核程序必须在对应位置全部抓到，抓不到即判核查失灵、不得交付 |
| 默认模型读得对 | 出片前列出全文所有数字（及缩写、专有名词）的实际读法，人工逐个确认 |
| 先交付后核查 | 顺序固定：核查全部通过 → 才推送 → 才发给用户；交付时如实报告核查结果 |

## 四、自检第一次运行就抓到的两个漏洞（2026-10-08）
加上"核查程序自检"后第一次运行，就证明了第 3 条原因是真的：
1. **复核门槛比出片标准宽（A13）**：故意把 "Hospital," 后面那个词的词头剪掉 60 ms，复核没报。原因：复核只把"比最响处低 45 dB 以内"算作听得见，而出片标准是词尾、词头保留到 -55 dB，中间差了 10 dB。已给复核加"A10 两侧核对"：每处删除，两侧 15 ms 内必须已衰减到 -55 dB 以下，删掉的部分不得高于 -40 dB。
2. **自检本身也会失灵（A14）**：第一版自检自己另算门槛判断"抓到没有"。把复核门槛故意改松（盲化测试）后，自检仍显示"全部抓到"。现在自检只认复核程序自己的判定；盲化测试下自检报"没抓到"、核查不通过，证明自检有效。
3. 改完后第01、02、03篇全部重跑《交付核查》出片后：自检 5 处全部抓到；独立复核词尾/词头被切 = 0，A10 两侧核对违例 = 0，多余声音 = 0（记录见 `音频核对/交付核查_0N.txt`）。
