# 视频与音频硬性条件（每支视频、每篇文章必须全部满足）

> 用户原话："音频的质量是我们的精髓……坚决不能出现任何瑕疵……以后做任何的音频和视频都要严格按照我们的硬性条件来。踩过的坑坚决不能再犯。"
> 开工前通读本页和《踩坑总表》；交付前逐条打勾。任何一条不满足，不得交付。
> **这些视频要作为教材使用**（用户原话："一定要保证我们这个做的视频非常非常的高质量……要作为教材去使用"）。踩过的坑一个都不能再出现。

## 〇、最高铁律（高于本页一切条款）
1. **这是教材，零瑕疵。** 任何一处读错、切音、卡顿、发闷、错字、错译，都会教错学生。宁可慢，不可错。
2. **踩过的坑绝不再踩。** 每做一篇，开工前逐条重读《踩坑总表》，用 `交付核查.py NN 对照表` 生成模板，在 `制作记录/NN.md` 逐条填写"踩坑对照记录"（本篇是否涉及、怎么防的）；没填完，出片前核查不通过。交付前再对照一遍。
3. **不自己检查自己。** 出片后必须用独立方法复核（与原始合成逐样本比对），并先做核查程序自检：在成片音频副本上故意造 5 处瑕疵（词尾、词头各轻切一处、重切一处，加一处杂音），复核程序必须在对应位置全部抓到，否则判核查失灵、不得交付。自检只认复核程序自己的判定；核查程序改动后做盲化测试（故意把门槛改松，自检必须报"没抓到"）。
4. **改一处，全部重查。** 出片程序、配音处理、停顿规则任何改动后，所有已出片篇目全部重跑《交付核查》。
5. **先核查，后交付。** 核查全部通过才推送、才发给用户；如实报告核查结果，不隐瞒、不夸大。
6. **专门的踩坑核查机制（任何东西交出去之前都要过）**：`工具/踩坑核查.py`。
   - 发 Word / HTML / PDF 前：`生成文本.py` 自动先跑 `踩坑核查.py NN 文本`，不通过就不生成、不发。
   - 出视频前：`交付核查.py NN 出片前` 自动先跑 `踩坑核查.py NN 出片`。
   - 做文章、视频以外的任何事之前：`踩坑核查.py 通用`，逐条对照沟通、保存类的坑和铁律。
   - 它做四件事：核查程序自检（在已定稿的第03篇副本里故意造出每一种坑，必须全部抓到、原稿不得误报）；踩坑对照记录逐条填完；能用程序查的坑逐条查；疑似问题（缺牛津逗号、数字对不上）逐个写明结论，换行与用户上次看过的版本逐句比对（L13）。
   - **新坑入表时，凡是能用程序查的，必须同时加进 `踩坑核查.py`，并在自检里加一个故意造坑的样本。**
7. **译文交付前必须独立审校**：由与译者无关的审校员，按第01–03篇定稿风格（《翻译风格》）和《踩坑总表》逐句、逐条审，每条意见再由裁判逐条反驳核实，只采纳确实更好的。
8. 事故原因与措施见《音频事故复盘》。

## 一、音频（最高优先级）
1. **零瑕疵**：每一个词、每一句都要清晰、自然、好听、专业；不能有发闷、发哑、电流声、断续、吞音、尾音被切（如 ink 的 /k/）。
2. **音色**：Kokoro，am_michael 75% + am_fenrir 25%（voice_mb.npy），语速 0.95；后期 F 方案（AF.txt：B 原声 + 轻降噪，去 4800/9600 Hz 电流音）。不得私自改动。
3. **读得连贯，不能卡顿**：词与词之间绝不能出现人为停顿（A9：adds | context）。停顿只能落在标点处，位置用带时长输出的同版模型精确定位（只取时间，声音仍用原模型），并逐处核对。
   **词尾必须完整（A10）**：拉长停顿时只能删停顿中间的底噪和换气声，词尾保留到衰减至比本句最响 5 ms 帧低 55 dB、下一个词从 -55 dB 处开始保留（基准不得用单个采样峰值，A10b），绝不能删词尾的 s/f/z/t/k 等弱音；实际听到的停顿必须正好等于标准。每次出片前运行 `python3 视频/工具/标点停顿核对.py NN`，全部 OK 才能出片。
   **读音正确（A11）**：数字按标准英语读法朗读（年份 nineteen ninety-five、年代 the nineteen sixties、日期 the sixth of January）；每篇开工先列出所有数字逐个核对。
   **独立复核**：每次出片后，由独立检查员用自己写的程序（与原始合成逐样本对比）核对词尾、词头是否完整，停顿是否符合停顿表。
   **整句一次合成**：不得在逗号处切开分段合成（会让逗号后开头发闷，A8）。逗号停顿只把模型的自然停顿换成标准时长。
   **连读处插入停顿（A15）**：说话人在逗号处没有自然停顿时，停顿插在"离前一个词结尾最近的足够安静处"，绝不能插进下一个词（如 i……ts）；带时长模型每次运行略有不同，出片程序的结果必须不受它影响（改规则后多次独立运行比对）。
4. **停顿标准（每次生成视频必须严格按此表，程序常量 P_COMMA/P_LIST/P_HOLD/P_LEAD/P_PARA_EXTRA/P_TITLE/P_FIRST 与此表一致）**：

   | 位置 | 时长 |
   |---|---|
   | 普通逗号（, ; :） | 0.4 秒 |
   | 牛津逗号列举内的逗号（A, B, and C） | 0.2 秒 |
   | 行与行之间（无标点） | 不停，整句连读 |
   | 引号（双引号、单引号） | **不停顿**（2026-10-08 用户定）：配音时不读引号，屏幕照常显示 |
   | 句号（同段内） | 共 1.0 秒：读完 0.7 秒 → 换屏 → 0.3 秒开读 |
   | 段与段 | 共 1.2 秒：读完 0.7 秒 → 换屏 → 0.5 秒开读 |
   | 标题 → 正文 | 读完 0.6 秒 → 换屏 → 0.4 秒开读 |
   | 片尾 | 2 秒 |

5. **只朗读英文原文**：`{{…}}` 注解、`{{=}}` 等标记一律不读。
6. **自动音频检查**：每支视频生成后必须运行 `python3 视频/工具/audio_qc.py NN.mp4` 全部通过（削波、4800/9600 Hz 电流音、片中停顿超长、某句响度骤降）；出片程序找不到逗号处自然停顿时直接停止，不允许退回分段合成。
7. **逐句试听检查**：每次定稿前，疑似发闷、断续、读音不准的地方，必须做成短试听交用户确认；程序检测只作辅助，不能代替人耳。

## 二、翻译
1. 精准、地道、通顺；先写通顺整句，再逐词对齐，绝不为对齐牺牲通顺。
2. **用户亲自给出的译法一律优先，原样采用。**
3. 不添加原文没有的信息（需要补充的放括号，且要用户认可）。
4. 重点词中文词性 = 英文词性（adj→…的，adv→…地）；方向（before/after 等）逐个核对。
5. 比较/倍数结构与被比较对象合成一组；不连续短语两部分都加粗同色。
6. 需要背景知识的地方加括号说明（单独一行，在译文正下方）。

## 三、英文原文与重点词
1. 英文原文一个字不改，**唯一例外：牛津逗号**——三项及以上并列，and/or 前一律加逗号。
2. 用户点名的词立即加为重点词；新加重点词（含同根、同形、短语里的实词）若在别篇加粗过，**不加并提醒用户**；用户坚持则写入 `allow_clash`。
3. 每个英文重点词都有中文标记，速查表补齐"本文义 + 词性 + 词义 + 例子"。

## 四、画面
1. 16:9；每句一屏；英文在上，中文在正下方逐词对照，重点词中英同色，中文重点词两侧留小间隙。
2. **换行必须经用户同意**：不得擅自加、改、删换行；改完与用户上次看过的版本逐句比对换行。已定稿篇目全片逐像素不变。
3. 锁定换行后每屏字号铺满（宽 ≤1860、高 ≤1020、上限 100 号），中文 = 英文 × 0.72；括号注释计入宽度；数字、英文不拆行。
4. 片头：拼字版「朋克英语」标志 + 约 1.5 秒入场动画；**视频不写篇号**；「朋克英语」只出现在片头。
5. 修改阶段出 1080p 草稿；用户确认后才出 4K 定稿。

## 五、交付与保存
1. 每篇交付：视频、可编辑 Word（与视频一致）、HTML、PDF（一律用 `工具/生成文本.py NN` 生成并自动核对，不手敲命令，W9）；同步文章与速查表、70 篇合集、词库与 Excel（Excel 只存 GitHub）。
2. 运行 `check_all.py NN` 全部通过；渲染后逐屏截图检查；**生成后先确认成功、时长正常，再推送、再发给用户**（不得推送失败的产物）。
3. 每次改动及时推送两个仓库，推送后核对云端文件。
4. 未经用户明确同意，不部署、不公开发布。
5. 新踩的坑当场写进《踩坑总表》，并在本页补上相应硬性条件。

## 六、每篇交付核查流程（按顺序执行，缺一步不得交付）
1. **开工前**：通读本页与《踩坑总表》；`python3 工具/交付核查.py NN 对照表` 生成模板，逐条填完"踩坑对照记录"；列出本篇所有数字、所有三项以上并列（牛津逗号），逐个确认。
2. **译文**：独立审校（第〇节第7条）→ `生成文本.py NN`（自动先过 `踩坑核查.py NN 文本`）→ 发给用户逐句确认；用户改稿写回后再走一遍。
3. **出片前核查**：`python3 工具/交付核查.py NN 出片前`，必须"全部通过"：
   - 踩坑核查（`踩坑核查.py NN 出片`）：核查程序自检、踩坑对照记录逐条填完、能用程序查的坑逐条查、换行与用户看过的版本比对
   - 数字读法清单（人工逐个确认读法）
   - 标点停顿核对（每处停顿 = 标准，被删部分只有底噪）
   - 句首句尾核对（修剪掉的只有听不见的部分）
   - 停顿位置精确核对（A9/A15/A16）：自然停顿用逐帧对齐判位置；程序插入的停顿（说话人连读处）还必须看前后两段的段长比；任何报警都用实际声音（逐 5 ms 响度与频谱）查清再下结论
   - 无标点处停顿 ≤ 0.22 秒
4. **出片**：`make_video.py`（1080p 草稿；用户确认后才出 4K）。出片程序内部遇到停顿越界、要删的部分有词的声音，会直接停止。
5. **出片后核查**：`python3 工具/交付核查.py NN 出片后`，必须"全部通过"：
   - 自动音频检查（削波、电流音、停顿超长、响度骤降；标出的地方剪成试听）
   - 核查程序自检：故意剪坏的 5 处（词尾轻切、词头轻切、词尾重切、词头重切、杂音）全部抓到（A13、A14）
   - 独立复核（另写的程序与原始合成逐样本比对）：每一处改动，词尾/词头被切 = 0；删除处两侧 15 ms 内都已衰减到 -55 dB 以下、删掉的部分不高于 -40 dB（A10 两侧核对；偏响的必须用实际声音确认是换气声/底噪并记录，A18）；多余声音 = 0
   - 生成本篇"标点试听"
6. **画面检查**：逐屏截图检查（无出屏、字号合理、重点词同色、换行与用户确认的一致）。
7. **交付**：视频 + 标点试听 + 所有疑点试听一起发给用户，并如实说明核查结果；用户试听确认后才算定稿。
8. **保存**：推送两个仓库并核对云端；新踩的坑当场写进《踩坑总表》和本页。
