# 第01篇视频制作记录与踩坑清单

《以为柠檬汁能隐身的劫匪》是第一支定稿视频，所有标准都是在做这一篇时一步步定下来的。本文按时间顺序记录每一轮修改的原因，最后汇总成"以后必须避开的坑"。

---

## 一、配音（声音）

| 轮次 | 问题 | 处理 |
|---|---|---|
| 1 | 要求男声、美音、有磁性、发音优美 | 试听多种 Kokoro 音色，选定 `am_michael` + `am_fenrir` 各 0.5 混合（voice_mf.npy），语速 0.92 |
| 2 | 句尾有"电磁音" | 起初误以为是句尾杂点，去尾时把 cameras 的 /z/ 尾音切掉了——**错**。逐句分析后发现高频尾巴是真实的 s/z 擦音，只能去掉极短的低能量杂点 |
| 3 | 整段背景仍有"隐隐约约的电子声波音" | 频谱分析找到真正元凶：Kokoro 声码器在 **4800 Hz 和 9600 Hz** 的固定音调。用陷波滤波器去除（AF.txt），复测这两处已降到周围噪声水平 |
| 4 | 停顿 | 标题后 1.2 秒；段落之间 1.0 秒（用户指定） |

## 二、画面

| 轮次 | 用户意见 | 处理 |
|---|---|---|
| 1 | 16:9、一句一屏、重点词彩色、中文在英文下方且同色 | 建立渲染程序 |
| 2 | 背景色 | 用户选"护眼绿"第二方案（深绿） |
| 3 | 一句话拆成上中下三段放在同一屏 | 采用"跟读高亮"：正在读的一段亮，其余变暗 |
| 4 | 字太小，要尽量铺满屏幕 | 自动适配字号 |
| 5 | 重点词前后要有小空格 | 中文重点词两侧加窄空格 |
| 6 | **每个英文词正下方对准它的中文** | 改为"逐词对照"排版：每个词/词组一列，中文居中放在正下方 |
| 7 | 不要为对齐而硬拆，中文必须通顺 | 规则：先定通顺整句，再往英文上对；对不上就合并成一组 |
| 8 | 一行能放下却被拆成两行 | 优先放一行；加入手动换行标记 `["\n",""]` |
| 9 | 换行后最后一行只剩一个词（如 "ink,"） | 改为"均衡换行"，两行长度尽量相等 |
| 10 | 某几屏字突然变小，不统一 | 曾改为全片统一字号 |
| 11 | 汉字太小 | 中文/英文字号比 0.62 → **0.72** |
| 12 | 数字 1999 被拆到两行 | 中文排版时数字、英文连续字符不拆 |
| 13 | 字还是小，要"在不改变换行的前提下铺满屏幕" | 最终方案：**锁定既定换行**，每屏放到最大（宽 ≤1860、高 ≤1020，上限 100 号） |
| 14 | 括号注释太长会压住整屏字号 | 字号计算时把注释宽度算进去，避免注释被截断 |
| 15 | 正文页顶部的小标题没必要 | 删除 |
| 16 | 括号说明要单独一行、放在译文正下方 | `note` 字段；"另译"用黄字（`#Y` 开头） |

## 三、标题页

| 轮次 | 用户意见 | 处理 |
|---|---|---|
| 1 | 标题页偏上、不醒目 | 居中、放大 |
| 2 | "完全没有特色、没有亮点" | 重新设计：超粗英文大字；"Lemon Juice"柠檬黄→橙渐变发光；"Invisible"从左往右渐隐、碎成光点；右下角大号篇号水印；中央柔光 |
| 3 | 中文色块不要椭圆，要圆角长方形 | radius 改为 18 |
| 4 | 色块里的字上宽下窄、不居中；字再大点 | 按字形实际边界（textbbox）上下居中；中文字号 ×0.57 |

## 四、停顿（最终）

| 位置 | 时长 | 变化过程 |
|---|---|---|
| 逗号处（行与行之间、行内逗号） | **0.6 秒** | 0.5 → 0.4 → 0.6；行内逗号原由配音模型自读约 0.28 秒，改为在逗号处切开分段合成再插入 0.6 秒 |
| 句号：读完静止 + 换屏后静止 | **0.7 + 0.3 = 1.0 秒** | 0.3+0.2 → 0.5+0.3 → 0.7+0.3 |
| 段与段之间 | 再加 0.5 秒 | — |
| 标题后 | 1.2 秒 | — |

## 五、翻译（最重要）

用户反复强调：**精准、地道、通顺**，每个词既精准又地道。

| 问题 | 错误 | 改正 |
|---|---|---|
| 添加原文没有的信息 | rubbed on → "涂抹在**脸上**" | 原文没说脸，后经用户审定为"涂抹在身上" |
| 词性错 | earnest → "真心实意**地**"（副词） | 形容词 → "真心实意的" |
| 词性错 | conviction → "深信"（动词） | 名词 → "信念" |
| 意思反了 | before → "之后才" | before 必须是"之前"："在他把自己的自由赌在抢劫上之前" |
| 对不齐 | logical reasoning、quarter of scorers、statistical mirage 的中文横跨两个词 | 拆开逐词对准 |
| 生硬 | 逻辑的推理、高成就者、得分者 | 逻辑推理、成绩优异者、答题者 |
| 读者看不懂 | "隐形墨水"是什么？ | 加括号：用柠檬汁在纸上写字，干后看不见，加热才显出字迹 |
| 读者看不懂 | 他为什么以为自己隐形了？ | 加括号说明自拍没拍到他 |
| 用户审定 | 用户亲自提供逐词译文（Word 文档）作为底稿 | 视频严格按用户译文；整句以用户的"整体连句翻译"为准 |
| 新增重点词 | 用户要求 accomplice、ink、invisible、calls for 作为重点词 | 已加入并上色 |

用户审定的个别译法：rationale→逻辑；proposition→观点；sheer→完全，disbelief→不相信；traced…to→查明…源于；staking→赌；turned on→转动（将镜头）对准。

## 六、文字稿与文档

- 视频对照文本要能编辑 → 生成 **Word（.docx）**，配色、换行、注释与视频一致；另有网页版和 PDF。
- 视频定稿后，用视频译文**反向更新** `新版定稿/01-*.md` 的英文加粗、中文译文和速查表（`工具/sync_article.py`），保证文章与视频一致。

## 七、保存

- 每支视频定稿后**立即**推送到两个 GitHub 仓库。
- 配音模型（325MB）超过 GitHub 单文件 100MB 上限 → 拆成 4 段 + SHA256 校验 + `资源/还原.sh` 一键还原。
- 保存后要**从云端重新下载核对校验码**，不能只看本地状态。

## 以后做视频必须避开的坑（检查清单）

### 翻译
1. **不得添加原文没有的信息**（"脸上"之类）。
2. **重点词中文词性 = 英文词性**：adj→"…的"，adv→"…地"，n→名词，v→动词。
3. **逐词核对意思方向**：before/after、increase/decrease 这类不能弄反。
4. 先定一句**通顺精准的整句**，再往英文上对；能对就对，不能对就合并，绝不为对齐牺牲通顺。
5. 每组中文只能包含它上方英文的意思，不能混入别的词。
6. 读者需要背景知识才能懂的地方，加括号说明（单独一行）。
7. 固定搭配整体作为一个重点单位：in broad daylight、rubbed on、devoid of、calls for、begged to differ……
8. 英文原文一个字都不能改，只调整加粗和切分（sync 脚本会断言检查）。

### 排版
9. 不要让程序自己决定换行：长句手动指定换行点（`["\n",""]`）。
10. 能放一行的不要拆两行；拆行时避免最后一行只剩一个词。
11. 字号：锁定换行后铺满屏幕；括号注释也要算进宽度，否则会被裁掉。
12. 中文里的数字、英文不能被拆开。
13. 渲染后**每一屏都要截图检查**，特别是最长、最挤的那几屏。

### 声音
14. 去噪只用 4800/9600 Hz 陷波，不要乱切句尾（会切掉 s/z 尾音）。
15. 行内逗号要分段合成，才能精确控制 0.6 秒停顿。

### 文件
16. Word 文档用表格做逐词对照，背景深绿；打印需勾选"打印背景色"。
17. 中文文件名在某些工具（LibreOffice 转换）下会失败，必要时先复制成英文名。
18. align 里的换行标记 `"\n"` 不能进入英文正文（拼接 en 时要过滤）。

### 保存
19. 定稿即推送，两个仓库都推；推送后从云端重新下载核对校验码。
20. 大于 100MB 的文件要拆分保存并附还原脚本。
