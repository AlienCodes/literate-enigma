## 要回答的问题（全部用实测数据，不凭感觉）
1. **能不能在 GitHub 上跑**：整条声音流程（合成 → 疑点清单 → 调平 → 体检 → 机器复听 → 读音核对 → 出片前/后声音门）在 GitHub 机器上跑通，结果与沙盒逐样本一致（单线程合成后）。
2. **能不能比沙盒更好**（GitHub 才有的条件）：
   - 机器复听换更大更准的识别模型（whisper medium/large-v3，或两个不同识别器投票），误报更少、漏报更少——用 01–27 已知的真问题和已知误报做标准答案，量查准率/查全率；
   - 加自动音质打分（UTMOS / DNSMOS / NISQA 这类 MOS 预测模型，HF 可下），每句打分，低于 01–26 基线就停或换版；
   - best-of-N 真正做大：20 台机器并行，每句多试几种语速/停顿，用 机器复听 + 体检 + MOS 打分挑最好的一版（W 正在做逐句语速字段，等它落地再接）；
   - 合成精度：kokoro 有没有更高精度的模型版本（fp32 对比现用的），同一句对比 MOS 和体检；
   - **换音色/换配音模型属于用户已认可声音的大改，不许自己换**：只做 A/B 试听样本（同一句旧/新各一个，一次只发一个，过发文件闸门），用户听了说换才换。
3. **成本和时间**：每篇在 GitHub 上整条声音流程要多久、会话花多少 token（应比沙盒少很多：会话只触发、看结果）。
