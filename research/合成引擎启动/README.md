# 合成引擎启动不了（v18.2 老师第一次真实训练后）→ v18.4 的修复和全流程核查

## 1. 现象（10-02 15:43，老师的 v18.2，Windows，8 GB 显卡）

- 训练成功（用时 30.6 分钟），但训练后「自动挑选最像你的模型」和手动「重新挑选最佳模型」都停在
  第 2 步「启动合成引擎」，等满 10 分钟后报「GPT-SoVITS 没能启动」（`RuntimeError: GPT-SoVITS 推理服务启动超时`）。
- 「详细过程」里每 15 秒一行「推理服务启动中……已等待 N 秒」，一直到 600 秒。

## 2. 证据：老师发来的 gptsovits_api.log

整理结果见 [`老师的gptsovits_api.log_整理结果.txt`](老师的gptsovits_api.log_整理结果.txt)（原文件 3.1 MB、36468 行，没有放进仓库）：

| 项目 | 数 |
|---|---|
| 启动次数（Started server process） | 3 |
| `Uvicorn running on http://127.0.0.1:9880`（引擎已经开好） | 3 |
| `"GET /tts HTTP/1.1" 500` | **867** |
| `"GET /tts HTTP/1.1" 400` | 0 |
| 报错种类 | 只有一种：`AttributeError: 'NoneType' object has no attribute 'lower'`（867 次，`api_v2.py` 第 484 行） |

## 3. 根本原因

- v18.2 判断「引擎好了没有」用的是**不带参数的 `GET /tts`**，并且只认 400 + JSON。
- 真实的 `api_v2.py` 在检查参数**之前**先执行 `"text_lang": text_lang.lower()`。不带参数时 `text_lang` 是 None，
  所以报错回 500。从第一版（52c50c6，2024-08）到现在（abe9843，2025-12）所有官方版本都是这样。
- 引擎其实一分钟内就开好了，程序却一直以为它没好，等到 600 秒超时。
- **测试为什么没发现**：我们的模拟版（`tests/fake_gptsovits.py`）对不带参数的 `GET /tts` 回 400，照抄了程序自己的假设，而不是真实引擎的行为。
- 老师的 `api_v2.py` 是 abe9843 / 6fb441f 那一版（报错在第 484 行）。整合包文件夹名里的 20250604 只是打包日期，里面的代码更新过。

## 4. 怎么修的（v18.4）

| 改动 | 文件 |
|---|---|
| 就绪检查改用 `GET /control`（不带 command）：所有官方版本都回 400 `{"message":"command is required"}`，而且什么也不做。兜底认 `/openapi.json` 里的 `/tts`。每次检查用新连接（`Connection: close`） | `backends/gptsovits.py` `_probe()` |
| 端口开了、但回答对不上：60 秒内报 `api_mismatch`（不再白等 10 分钟）。超时 / 启动失败的报错带自动诊断和整理过的引擎记录 | `start()`、`_api_report()`、`utils/logtail.py` |
| 引擎记录每次启动写分隔线（`===== 声音分身 …`），超过 5 MB 先改名 | `start()` |
| 只接着用自己开的服务（或 config 里的 api_url），端口上别人留下的 api_v2 不接手，换端口自己开 | `start()` |
| Windows 作业对象：声音分身怎么结束，GPT-SoVITS 的推理服务和训练进程都一起结束 | `utils/winsys.py` `kill_with_parent()` |
| 真实 `TTS.run` 出错（比如显存不够）不报错，回 200 + 1 秒 16 kHz 静音（TTS.py 第 1516~1518 行）：认出来，从引擎记录里找真正的原因 | `synthesize()`、`_silent_answer()`、`_last_exception()` |
| 半精度时 tanh 正好 1.0 → `*32768` 溢出成 -32768（满幅度「咔哒」）：两边是正数的改回 32767 | `_fix_int16_wrap()` |
| 换模型失败显示真正的原因；模型文件找不到先说清楚（真实 TTS_Config 会悄悄换成底模） | `_set_weights()`、`start()` |
| 训练前建 `SoVITS_weights_<版本>` / `GPT_weights_<版本>`（真实训练脚本不建） | `_train_sovits()`、`_train_gpt()` |
| 句首没有空白时只淡入 4 毫秒（真实输出开头就是声音） | `synth/engine.py` `trim_edges()` |
| 去掉没测过的「第一次大约 1~2 分钟」：改成实测的「上次用了 N 秒」 | `start_hint()` |
| 自动挑选：某个模型文件坏了跳过；显存不够等「重试也没用」的错误直接报出；引擎中途重启还用正在试的模型；识别校验出错就关掉它接着挑 | `synth/select.py` |
| 生成：识别校验出错就关掉它接着生成 | `synth/engine.py` |
| 出错自动生成「问题报告」：「详细过程」里写简短的，`logs/问题报告_日期_时间.txt` 存完整的 | `voicetwin/report.py`、`webui/tasks.py`、`workflows.run_train` |

## 5. 怎么保证以后不再出现这一类问题

- `tests/gsv_real/` 放了**真实的** `api_v2.py`，两个版本：abe9843（老师的版本）和 20250606v2pro，MIT 许可。
  `tests/test_gsv_real_api.py` 直接运行它，只把模型换成假的（`fake_gptsovits.REAL_API_STUBS`，照着真实 TTS.py 的检查和输出格式写），
  跑通「启动 → 换模型 → 合成 → 停止」和「训练 → 自动挑选 → 生成」整条流程。
- **把新测试放到 v18.3 的旧代码上跑：失败**，报的正是老师遇到的「推理服务启动超时」（[`新测试在v18.3旧代码上的结果.txt`](新测试在v18.3旧代码上的结果.txt)）。
  说明这套测试能抓住这一类问题。
- 模拟版改成和真实行为一致：不带参数的 GET /tts 回 500；/control 不带 command 回 400；显存不够时回 200 + 静音；
  训练脚本不建权重文件夹。
- 复现脚本：[`复现脚本/repro_alive.py`](复现脚本/repro_alive.py)、[`复现脚本/e2e_start.py`](复现脚本/e2e_start.py)
  （开发时在临时目录里用，路径要按实际改）。

## 6. 全流程排查（两轮多助手调查，都对照真实源码）

**第一轮**：查「引擎为什么一直没就绪」。6 个角度：就绪检查、阻塞、配置、进程、显卡、诊断。每个角度都独立复现出了同一个原因。
排除了这些可能：加载模型卡住（时间点对不上：每次检查约 2.02 秒，说明端口是开着的）、显存不够、端口冲突、代理拦截。

**第二轮**：查「还有哪些地方程序的假设和真实 GPT-SoVITS 不一样」。4 个角度：HTTP 接口、模拟版和真实的差别、训练后从没真跑过的流程、Windows。
查出来并修好的问题见上表。确认没问题的有：
- 训练请求的每个字段都能通过真实 api_v2 的检查（zh / en、cut0、streaming_mode=False）；
- 输出是 32 kHz、PCM_16、开头没有空白、后面补 0.3 秒的 0（程序切掉首尾空白，不影响停顿和语速）；
- 参考音频 3.2~9.8 秒，符合真实的 3~10 秒要求；随机种子在 2³² 以内；
- 权重文件名、版本标记的解析和真实一致；子进程输出是 UTF-8。

**考虑过、这次没改的**：
- 自动挑选时先加载识别模型、再开引擎（生成时顺序相反）。估算 8 GB 显卡上两边加起来约 4.3~6.1 GB，放得下；
  改顺序要连带改进度条的步骤，所以这次没改。识别模型加载失败时本来就会跳过识别校验。
- pid 文件清理旧引擎：有了 Windows 作业对象和「不接手别人的服务」，不需要了。

## 7. 核查：改好的文字才是训练用的，删除的句子不用（老师 10-02 的要求）

`tests/test_material_flow.py` 按老师在网页上的顺序做一遍：改字 → 保存修改 → 删除两行（一条参考音频、一条考试题）→
再改一句不保存 → 开始训练（被拦住）→ 确认训练素材 → 训练 + 自动挑选。然后逐项检查：

| 检查 | 结果 |
|---|---|
| 交给 GPT-SoVITS 的训练列表（train.list） | 改过的那句是改好的字；删除的两条不在；里面的句子正好是「没删除、能用、不是考试题」的那些 |
| GPT-SoVITS 自己处理文字那一步（1-get-text.py 的输出） | 是改好的字；没有删除的那两条 |
| 参考音频（references.json） | 没有删除的那条；每条配的文字和校对表里保存的一样 |
| 自动挑选时 GPT-SoVITS 实际收到的每个请求 | 不用删除的音频当参考（主参考和辅助参考都不用）；参考文字是保存好的字；不读删除的那句考试题 |
| 有没保存的修改时点开始训练 | 不开始，提示先保存（`unsaved_edits`） |
| 训练以后又改了字 / 撤销删除 | 训练页和生成时提醒「需要重新训练」（按训练时记下的列表指纹比，旧版本训练的模型也能判断） |
| 改了参考音频的文字以后 | 生成缓存的键会变，不会用改之前生成的声音 |

核查中修好的地方：
- 没保存的修改会被训练忽略：现在直接不让开始训练，并说明原因。
- 删除的句子之前还参与「语速离群」统计和「像不像本人」的声纹平均值：现在不参与。
- `load_manifest(only_kept=True)` 再保险一次：删除的一定不算。
- 生成缓存的键加上参考文字。
- 训练开始时在「详细过程」里写清楚：这次用多少条、其中多少条是改过文字的、删除的多少条不用。

注意：删除了一条「考试题」以后，程序会补一条新的考试题（不训练，用来挑最像的模型）。补到的如果是刚改过的句子，
它就不进训练列表，但挑模型时读的是改好的字。这是设计如此（大约 20 条考试题），校对表上方写着「其中 N 条当考试题」。

## 8. 真实浏览器实测（gradio 4.24 + Python 3.9，和老师整合包同版本）

脚本和截图：`research/过程文件/04_浏览器实测/m28_v18.4引擎与确认/`（`setup.py` 建假整合包，推理服务用真实的 api_v2.py；
`run_webui.py` 启动网页；`check.py` 用 Playwright 点一遍）。结果 **16/16 通过**（`check_结果.txt`）：
- 没确认训练素材：训练页写着「还没有确认训练素材……」，点「开始训练」不开始（没有训练列表），也不生成问题报告；
- 点「✅ 确认训练素材」→ 回到训练页提醒消失 → 开始训练 → 自动挑选成功（「像你本人 68.0%」是假模型的数，没有意义）；
- 引擎记录里除了停止时的 exit 没有 500；
- 把引擎弄坏（拿走 TTS.py）后点「重新挑选最佳模型」：**3 秒**就报出原因，「详细过程」里有问题报告（原因 + 自动诊断出的线索），
  logs 里有完整的报告文件（含引擎记录、电脑情况）；
- 引擎修好后「③ 生成讲课音频」走完，存下了音频文件；网页上没有脚本错误。

实测中发现并修好：确认训练素材以后回到训练页，刚才的「还没有确认」提示还留着 → 回到训练页时去掉（`refresh_train_bar`）；
页面顶部的「下一步」在没确认时改成先去确认。
