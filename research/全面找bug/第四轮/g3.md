## 1. 没保存的修改抄了一份「保留 / 语言」，程序后来改了，保存时把旧的当成老师选的写回去（review#1）

- **问题**：还没识别出文字的灰色句子，老师自己打了字（没保存），再点「开始准备素材」识别出文字、程序判断能用了；
  点「保存修改」以后这句被固定成「不用」（manual_keep=False），以后每次准备素材都不用它，页面还说「1 条改成了要用 / 不用」。
  反过来，草稿里抄的「要用」也会把程序后来判成不能用的句子（声音不像本人）硬塞进训练；抄的语言也一样会把 Excel 里改的语言改回去。
- **原因**：每条草稿把文字、保留、语言三样都抄一份；保存时拿抄的值和**现在**保存的值比，不一样就当成老师改的。
- **怎么修**：每条草稿多记一个 `own`：真的改过哪几样（自己改字、采用建议、替换、一键校正记「文字」；「这一条也要用」记「保留」；
  双击「语言」记「语言」）。没改过的那几样一律跟着保存过的走（`current_values`，表格显示、数没保存的条数、保存都用它）；
  语言没手动改过时按保存时的算法跟着文字走（`follow_lang`，和 `apply_text_edit` 一样）。保存用 `current_values` 算出的值。
  旧版本存的草稿（没有 own）：和以前一样按草稿算，只有「不用」例外（表格里只能改成「要用」，草稿里的「不用」只可能是抄的）；
  网页数没保存的条数时（`prune_draft`）顺手记下改过哪几样。一键校正（`adopt_all_suggestions`）、文字校正（`transcript_fix`）
  改草稿也改成 `put_text`（只记改了文字）。`set_draft` 的参数没变。
- **测试**：`test_review.py` 的 `test_typed_text_on_grey_clip_is_not_pinned_unused_after_prepare`（真的准备素材 + 假识别引擎）、
  `test_unsaved_edit_does_not_force_a_clip_the_program_dropped`、`test_unsaved_edit_does_not_put_back_an_old_language`、
  `test_old_drafts_without_own_fields_still_work`、`test_one_click_adopt_keeps_following_the_saved_keep`。

## 2. 写文件从来不 fsync，保存以后几秒内断电，manifest.jsonl 变成空的或一堆 0（review#2）

- **问题**：保存修改、删除一行、准备素材识别时（每 20 条存一次）、🔍 自动查找时，写完只交给系统；Windows 断电 / 死机以后
  「换过了」记得、内容没写进去，开机 manifest.jsonl 是空的或全是 0，整张校对表没了。照着网页说的再点「开始准备素材」，
  transcripts.csv 也被空表冲掉，最后一份改好的文字也没了。
- **原因**：`atomic.write_text` / `export_csv` 写临时文件、`os.replace` 换上去，中间没有 `fsync`（strace：一次保存 12 次换文件、0 次 fsync）。
- **怎么修**：
  - `atomic.finish` 换文件之前先 `fsync` 临时文件（`atomic.sync`），所有用 `atomic.finish` / `write_text` 的地方（校对表、
    transcripts.csv、草稿、确认记录、缓存）都一样；个别盘不支持 fsync 时照样保存。写法（换行）和以前一字不差。
  - `export_csv`：这次要写的比上次写的少了句子（正常只会多不会少，删除也只是标紫色）时，先把上次的 transcripts.csv
    另存成 `transcripts_备份_时间.csv` 再写（`_keep_old_csv`，靠上次写的 `transcripts.exported.json` 判断）。
    **这一条第一版不够，审查以后重做了，见文末「审查以后」。**
  - manifest.jsonl 在、却一条都读不出来、切好的片段还在：在黑色窗口 / 记录里说一次（多半是断电）。
  - `.bad` 副本以前只留第一次的：第一次那份什么都没有（空的 / 全是 0）时换成后来有内容的那份。
  - **没有做**：manifest 丢了以后自动把视频重新切一遍。这正是 g4 组 pipeline#8 的修法（`sources.json` 说处理过、校对表里却一条都没有
    的视频当成没处理过），在 `prepare.py`，不在这一组改，免得两组改同一段；按片段编号把备份里的文字自动填回去也没做——重新切的时候
    片段的边界可能和原来差一点，编号一样不等于是同一段录音，填错了就是用错的文字训练。备份的 csv 留着，可以人工找回。
- **测试**：修以后用 strace 看一次「改一句 + 保存修改」：5 次换文件、5 次 fsync（每次换之前一次）。
  `test_atomic.py` 的 `test_files_are_on_disk_before_they_replace_the_old_ones`（每次换文件之前都先 fsync）、
  `test_fsync_not_supported_still_saves`、`test_empty_manifest_does_not_wipe_the_last_copy_of_the_texts`、`test_useless_bad_copy_is_replaced`。
- **代价**：每次保存多一次落盘，固态硬盘一般几毫秒，机械硬盘 / U 盘 / 网盘可能几十毫秒以上（没在老师的电脑上量过）。

## 3. 撤销最后一条修改时删不掉草稿文件，Windows 上悄悄失败（review#3）

- **问题**：只剩一条没保存的修改时「撤销这一行的修改」（或者把字改回原样），同一时刻别的按钮正在读草稿文件（例如删除一行以后
  刷新「一键全部文字校正」的状态）：Windows 不让删，程序吞掉错误，页面说「已撤销」，下次「保存修改」却把撤销了的字存进训练素材。
- **原因**：`save_draft({})` / `_save_rejected({})` 里 `unlink()` 出错直接 `pass`；换文件有「等一会儿再试」，删文件没有。
- **怎么修**：新的 `atomic.remove`：删不掉（PermissionError）和换文件一样等一会儿再试（最多约 3 秒）；还删不掉就把内容写成 `{}`
  （读的地方当作没有）；都不行才报错（网页显示出错，不再说「已撤销」）。草稿、撤销记录、「撤销刚才的替换」的记录都用它。
- **测试**：`test_review.py::test_revert_survives_a_briefly_locked_draft_file`、`test_atomic.py::test_remove_retries_and_never_pretends`。

## 4. v18.2 ~ v18.4 的确认记录一直不升级，升级以后只改语言照样能训练（review#4，第三轮 3.3 第 1 条没修完）

- **问题**：v18.4 确认过训练素材，升级以后把一句从中文改成英文、保存，再点「开始训练」：照样开始，表格上方还写「✅ 已确认」。
- **原因**：旧记录没有 `sig_version`，一直按旧算法（只有句子和文字，没有语言）比；确认记录只有「确认训练素材」才会重写。
- **怎么修**：`upgrade_confirmed`：旧记录还和现在的素材对得上，就原样换成新算法（确认时间、数量不变，升级照样不用重新确认）。
  打开校对表就会读到（`load_confirmed`），「保存修改」（`save_rows`）、读回 Excel（`import_csv`）写之前也先换——不然第一个读到的
  是「开始训练」时，已经保存的语言修改会被当成确认过的。已经对不上的旧记录不动（照样要求重新确认）。写不了就算了、下次再试。
  「开始训练」被拦下时的说明加上「语言」。
- **测试**：`test_bug_hunt.py::test_old_confirmation_is_upgraded_so_a_language_change_counts`（网页、只保存、Excel 三条路 + 已经对不上的不动）。

## 5. 替换被表格的统一写法改回去，还说「已经把 N 处换成…（🔴 没保存）」，冲掉上一次替换的撤销记录（review#5）

- **问题**：查找「,」替换成「，」：英文后面的逗号表格一律存半角，换完马上又变回去，什么都没变，页面却说换了 5 处、没保存；
  「↩️ 撤销刚才的替换」再也撤销不了上一次真正的替换；「替换这一处」一直停在同一处。
- **原因**：判断「换没换」用的是没整理过的文字（`new == text`），整理（`clean_transcript`）以后其实一样。
- **怎么修**：先整理再比，一样的不算、不记撤销（返回 `same`）；网页说清楚为什么没换（表格会自动统一标点：英文后面半角、汉字后面全角），
  「替换这一处」跳到下一处。
- **测试**：`test_review.py::test_replace_that_cleanup_turns_back_is_not_counted`（数据 + 网页两个按钮）。

## 6. 「撤销刚才的替换」把老师后来选的语言也改回去（review#6）

- **问题**：替换一个词以后，老师把那一句的语言从英文改成中文，再撤销替换：语言悄悄变回英文，还算「改回去了」。
- **原因**：撤销只比文字，然后连语言一起设回替换以前的。
- **怎么修**：撤销记录里多记替换以后的语言（`after_lang`）。撤销时语言已经不是它了（老师后来改过）→ 只把文字改回去，语言照老师选的；
  语言是老师手动选的 → 改回替换以前的；别的 → 语言跟着文字自动换（替换让语言自动变了的，撤销时照样变回来，也不算老师选的）。
- **测试**：`test_review.py::test_undo_replace_keeps_the_language_chosen_afterwards`。

## 7. 确认训练素材还在跑的时候做的「全部替换」，撤销记录被确认删掉（appB#3，v18.5 修法带来的）

- **问题**：点「✅ 确认训练素材」（重新统计音频要几秒，页面没有进度），这期间点了「全部替换」（查找的按钮和表格的按钮各排各的队，
  会同时跑）：确认做完把这次替换的撤销记录也删了，「撤销刚才的替换」说没有可以撤销的；还说「✅ 训练素材已确认」，换好的句子却没保存。
- **原因**：确认最后无条件 `clear_undo`。
- **怎么修**：保存的那一刻（拿着锁）记下撤销记录的原样（`undo_stamp`），做完时还是它才删；替换的撤销记录加上每次都不一样的 `seq`。
  确认结果里多一个 `unsaved`，网页说「确认的时候又改了 N 句（🔴 还没保存）：这次确认的是改之前的样子……」，有撤销记录时提一句可以撤销。
  没有把替换按钮挪到表格的队伍里：那样会和「上一处 / 下一处」同时写查找记录，或者让它们排在 3 秒的表格操作后面。
- **测试**：`test_bug_hunt.py::test_confirm_keeps_the_undo_of_a_replace_made_while_confirming`（数据 + 网页说明 + 确认期间没替换时照样删）。

## 审查以后：transcripts.csv 的备份只看编号，断电时一起坏 / 视频重新切一遍就不备份（审查 review#2）

- **问题**（审查的人复现，我在现在的代码上也复现了：`g3_审查_复现.py`，修以前两种都是 BUG）：
  1. `transcripts.exported.json` 和 manifest.jsonl 是同一次保存写的（它最后写），断电时常常一起变成一堆 0 / 空文件。
     以前只靠它判断「少了句子」，它坏了就不另存：再写一次表格，transcripts.csv 里 5 句改好的字被空表冲掉，备份 0 份。
  2. manifest.jsonl 和 sources.json 都坏了（或者和 g4 组合并以后：sources.json 说处理过、校对表里一条都没有的视频再切一遍），
     照着网页说的再点「开始准备素材」：视频重新切一遍，**片段编号和原来一模一样**，只比编号看不出少了什么，
     字幕 / 识别的字把老师改好的字冲掉，备份 0 份。第一版在黑色窗口里说的「程序不会再用空的校对表把它冲掉（会先另存一份备份）」
     在这条路上是假的。
- **原因**：`_keep_old_csv` 只在「上次写的编号这次没有了」时另存，而且只认 `transcripts.exported.json`。
- **怎么修**（都在 `project.py`，没动 `prepare.py`，免得和 g4 组改同一段）：
  - **读的时候记下来**：`load_manifest` 发现 manifest.jsonl 空了 / 有坏行 / 不见了，而 transcripts.csv 里还有句子（或者有内容却
    读不出来），写一个 `manifest.lost.json`（`_note_lost_manifest`）。下一次写 transcripts.csv 以前**一定**先另存，写成功以后才删掉
    这个记号。记号在硬盘上：准备素材重新切好、存了校对表、还没写 transcripts.csv 就被停止 / 关掉程序，下次写的时候照样另存。
    老师只删了几句（紫色）、没改字的时候，比编号、比文字都看不出来，只能靠它。
  - **比文字**：上次写的一句有字，这次要换成别的字，这一条却没有「被人改过」的记号（`text_edited`）→ 另存。程序自己从来不改
    有字的句子（查过：改文字只有 `apply_text_edit`，它一定记 `text_edited`；识别只填没字的句子），所以正常保存不会误报。
  - **上次写的看不到就读 transcripts.csv 本身**：`transcripts.exported.json` 坏了 / 没有，就直接读 transcripts.csv 里的编号和文字
    （`_csv_texts`，UTF-8 读不了再试 GBK——Excel「另存为」的默认）；有内容却读不出来（乱码、表头被改了）也另存。
  - transcripts.csv 自己是空的 / 一堆 0：没有可留的，不另存；和已有的一份备份一模一样也不再另存（例如 Excel 开着，这次又没写成，
    以前每保存一次就多一份一模一样的）。备份也先写到硬盘上再换上去（和别的文件一样 fsync）。
  - **另存不了就先不写 transcripts.csv**（报错；校对表 manifest.jsonl 已经存好了，下次再试）。以前说一句就接着写，上次保存的
    文字一份都不剩。
  - 黑色窗口里的话只说真会做的：transcripts.csv 里有句子才说「下次写它以前，程序会先把它另存成 transcripts_备份_日期_时间.csv」；
    没有就只说 manifest 空了 / 坏了、多半是断电。真的另存的时候说为什么另存、存在哪里、怎么用（用 Excel / WPS 打开，把文字抄回网页）。
  - **还是没有做**：按编号把备份里的字自动填回去（理由同上：重新切的边界可能差一点，编号一样不等于是同一段录音）。
- **淘汰的做法**：只比文字、不记号——老师只删了句子 / 只改了语言时看不出来；比「保留」那一格——程序重新过滤（例如加了视频以后
  「声音不像本人」重新算）本来就会改，会一直误报；每次文字有变化就另存——老师每保存一次就多一份备份。
