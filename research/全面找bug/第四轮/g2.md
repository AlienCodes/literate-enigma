## 1. 上传的讲稿里有同音错字，把表格里对的字改错（textfix#1）

- **问题**：老师上传自己用拼音输入法打的讲稿（或别的识别软件的文字），里面有「过去试」「主雨」「同位于」「度一下」「在来看」。
  表格里本来对的句子，一键校正**直接改成了错字**，还写「已按标准库改好」（复现：5 处全改错）。标准库术语也被改坏（宾语 → 彬鱼）。
- **原因**：① 和上传的句子 85% 以上一样时，读音一样 / 很像的字直接按上传的改；上传的文字没人修缮过，说不准是识别错了还是打错了。
  ② 「改完以后标准库马上又会说有错的不改」这一关用的标准库里也算上了上传的文字：上传里的一个「过去试」就让程序以为这是老师的说法，关就失效了。
- **怎么修**：① 只对上**上传的**（没修缮过的）句子的**单个汉字**不直接改：读音很像（声调不一样、影响训练）的只给**没把握的建议**
  （一键校正不自动采用，说明写「你上传的母本里是……」），读音完全一样的（不影响训练）不提示；对上程序自带母本的照旧直接改。
  ② 把关用的标准库只用程序自带的母本（`guard`）。英文被写成汉字（威驰 → which）这种照旧按上传的讲稿直接改。
- **测试**：`test_typos_in_an_uploaded_script_never_overwrite_correct_text`（修以前失败）、
  `test_correct_uploaded_script_still_fixes_recognition_errors`（对的讲稿照样有用：which 直接改，「度 → 读」给建议、点「采用」就改好）。
  老师 1004 句 6 种情况（不上传、修缮前 / 后的 csv、GBK csv、修缮前 / 后的 txt）都还是 123/123、多改 0（`teacher5.py`；
  「修缮后 txt」剩下标红 1 句，修以前也是 1 句）。
- **代价**：上传的讲稿是对的时，读音很像的单个字要老师点「采用」，不再自动改；读音一样的单个字不再提示（本来也不影响训练）。
- **复查时改了**（10-04）：两个字的词、英文拼写也一样拦；读音一样的单个字不再丢掉（母本优先），标准库也这么说的照旧直接改，见下面 R1、R2。

## 2. 上传太长：后面的文件悄悄不用，页面却说都用了（textfix#2）

- **问题**：程序自带的母本加上上传的超过 40 万字 / 词（`MAX_TOKENS`）时只用前面的，按文件名排在后面的整个没用上；
  页面写「另外用了你上传的：a、b」「也一起用」，这批素材唯一的一次也用掉了。表格里每做一个操作，按钮下面的说明都把上传的文字整个重读一遍（1 MB 约 1.5 秒）。
- **怎么修**：① 存之前数一下（和校对表一模一样的句子不算），超过 `upload_room()`（= 40 万 − 自带母本 41909 = 358091）就不存、
  不开始，说清楚一共多少、最多多少、请只上传这批录音的讲稿（上次的母本还在，一键校正也还能用）。
  ② 旧版本存进去的太长的母本：结果里只写真的用上的文件，另起一行「⚠️ 太长，只用了前面大约 N 个字 / 词：x（只用了前面一部分）、y（一点都没用上）」；
  按钮下面写「太长了：只用前面大约 N 个」，不写「也一起用」。③ 读过的文件按（名字、大小、修改时间）记住，不变就不再读（每次刷新 0.01 秒）；存新的时清掉。
- **测试**：`test_too_long_upload_is_refused_and_truncation_is_shown`、`test_upload_info_does_not_reread_unchanged_files`（都在修以前失败）。
  实测（`r_perf.py`）：1.37 MB 不存（2.9 秒说明原因）；1.07 MB 存好 3.8 秒，以后每次刷新 0.01 秒。

## 5. 🔍 查到一半点「停止」：一键校正去掉的标红和错的建议又回来了（proofcheck#1）

- **问题**：一键校正用母本证明「最」没错、去掉了标红；后来再点 🔍（或者加新素材时准备素材自动查）中途停止，「最 → 很」的错建议又回来了，
  一键校正的按钮是灰的，只能从头再查一遍；点了「采用」就把对的字改错。合在一起的那一步点停止也一样。
- **原因**：要和一键校正合在一起的行，先把没核对过的新结果写进了表格，合并只在**正常查完**以后才做；停止 / 出错时直接把这个样子存下来（每 20 条的中途保存也是）。
- **怎么修**：这些行先记下原来的标记；停止、出错、合并时停止 / 出错、每 20 条的中途保存，都把这些行放回原来的样子（下次 🔍 再查）。
  合并本身不在停止时做（停止信号还在，一做就停）。
- **测试**：`test_stopped_auto_check_keeps_the_one_click_results[checking/merging]`（修以前都失败）。

## 6. 校对表里打的「……」「！！」「（定语从句），」被改坏（proofcheck#2 = appB#6）

- **问题**：「……」变成「。.....」（多出一个句号，训练也学成句号），「！！」→「！!」，「？！」→「？!」，「（定语从句），」→「（定语从句）,」，「”，」→「”,」。
- **原因**：先做 NFKC（「…」变三个英文点、全角标点变半角），再只把**紧跟汉字的一个**标点转回来。
- **怎么修**：有中文时「…」「‥」先换成占位字符、整理完换回来；英文「...」跟在中文后面换成「……」；连着的几个标点整串转；
  中文的右括号、引号、书名号后面的标点也转（括号先还原）。英文后面的半角逗号（which,）、f(x)、3.5 这些照旧。
- **测试**：`test_clean_transcript_keeps_chinese_punctuation_the_teacher_types`（修以前失败）；程序自带母本 + 老师母本原文 / 修缮后一共 3021 句，
  新旧结果**一句都没变**（`cmp_corpus.py`），再整理一次也不变。已经存成「。.....」的旧文字不自动改（老师下次改这一句时会变成「。……」）。

## 7. 「第一种情况第二种情况」被标成「连着重复了 2 遍」（proofcheck#3）

- **原因**：比较是不是重复时，所有数字都当成同一个「#」；1~3 个字的有数字检查，4 个字以上的没有。

## 8. 英文例句说了两遍，删掉一遍还标着「重复了 2 遍」（proofcheck#5）

## 9. 撤销过 / 自己改过的改法，🔍 以后说明里还写着（proofcheck#6）

- **问题**：撤销过「王 → 黄」（或者自己改成「汪」）以后再 🔍，「王」不标红、也不建议了，说明里还写「另一个识别引擎听到的是「黄」」。

### R1. 上传的讲稿有错字：两个字的词、英文拼写还是直接把对的改成错的（textfix#1，上一次只修了单个字）

- **问题**：表格里对的「练习」「时候」「意义」「which」「sentence」，上传的讲稿里打成了「联系」「事后」「异议」「wich」「sentense」，
  一键校正直接改成了错的，还写「已按标准库改好」（复现：5 句全改错，上一版和更早的版本一样）。
- **原因**：上一次只拦了「只对上上传文字的**单个汉字**」，两个字以上的、英文（`en`）照旧直接改。
- **怎么修**（`check_text` + `_vetted_support`）：只对上上传的文字（没修缮过）的改法——汉字的别字（不管几个字）、英文拼写、
  「汉字被写成了英文」（which → 威驰，别的识别软件常这样）——要**程序自带的母本标准库也站在上传的那一边**才直接改：
  带上前后挨着的汉字数次数（先看左右各带一个字，再看只带左边 / 右边；单说「练习」「联系」两种都常说，证明不了），
  标准库里上传的写法出现过、并且是现在写法的 3 倍以上（`SUPPORT_RATIO`）才算；英文按整个词数。证明不了的**不直接改，也不丢掉**：
  按上传的母本给一个没把握的建议（一键校正不自动采用），说明写「……你上传的母本里的「联系」……；也可能是上传的文字打错了（它没有修缮过 /
  程序自带的母本里是现在这种写法）」，老师听录音点「采用」。「英文被写成了汉字」（威驰 → which）照旧直接改（上传的文字打错也打不成英文）。
  改完标准库马上会说写错了的（过去试、彬鱼）照旧不改、不建议。
- **测试**：`test_typos_in_an_uploaded_script_never_overwrite_correct_text` 加上 练习 → 联系、意义 → 异议、时候 → 事后、which → wich、
  sentence → sentense，并且要求每一处都显示成「你上传的母本里……」的没把握的建议（修以前失败）。
- **实测**（`复查_p1_upload.py`）：10 句一句都没改；9 处给了没把握的建议（「先行次」对照表本来就会改回「先行词」，没有要建议的）。

  老师说了母本最优先：如果老师希望**上传的讲稿也不用标准库证明、直接改**，把 `check_text` 里那个判断去掉就是（代价是讲稿里的错字会直接写进表格）。

### R3. 一键校正刚用上传的讲稿改好表格，按钮下面马上说「这个声音自己的文字……用不上」（textfix#3）

- **问题**：同一次点击的结果写「另外用了你上传的：这节课的讲稿.txt」，按钮下面却写「里面的句子和校对表里的一模一样（就是这个声音自己的文字），
  一句话不能拿来证明它自己没错，所以用不上」。只用了一部分时写「其中 1 句和校对表里的一模一样，那几句不用」。
- **原因**：按钮下面的说明拿上传的句子和表格**现在**的句子比；一键校正把表格改成了上传的样子，就分不清是本来一样还是刚改成一样的。
- **怎么修**：存母本的时候（`save_transcripts`）按一键校正同样的算法算好每一句用不用，记在逐字稿文件夹的 `_upload_info.json`
  （文件大小、修改时间、程序自带标准库的版本对不上就不用它）。说明分开写：「N 句已经拿来改好了表格里对应的句子（现在和表格里一模一样）」、
  「N 句上传的时候就和校对表里的一模一样（这个声音自己的文字）」、「N 句程序里已经带着了」；都用完了写「没有别的要比的了」。
  旧版本存的（没有记下）分不清，只写「N 句和校对表里现在的句子一模一样」。
- **测试**：`test_upload_info_after_the_one_click_used_it_is_true`（用了一部分 / 全用了 / 旧版本存的三种；修以前失败）。

### R4. 新的声音上传老师原来的 transcripts.csv：说「这是这个声音自己的文字……可以给别的声音当母本用」，存进去以后还说「也一起用」（textfix#3）

- **原因**：「和校对表一样」「程序自带的母本里已经有」两种用不上的情况混在一起说；按钮下面只去掉了和校对表一样的。
- **怎么修**：分开数（`_line_marks` / `_line_kind`，网页上不存时的说明 `_useless_upload_msg`、一键校正结果里的 `files_known` / `files_both`、
  按钮下面的说明都分开）：程序里已经有的说「里面的句子程序里已经带着了（就是你的母本标准库，每个声音都会用），不用再上传」。
  另外，没有 id 的 txt 里和程序自带的某一句一模一样的句子也算「已经有」，不再重复拿来比（以前只认同一个 id 的；修缮过的那一份照样在用，结果不变：
  老师 6 种上传情况照样 123/123、多改 0，「修缮后 txt」剩下的标红 1 句 → 0 句）。
- **测试**：`test_uploading_the_builtin_mother_again_is_explained_truthfully`（csv 和没有 id 的 txt；网页上不存、按钮还亮；命令行存进去以后
  按钮下面不说「也一起用」；一键校正结果说「程序里已经带着了」，不说「证明它自己没错」；修以前失败）。
- 顺手：`_clean_uploaded` 里对照表左边的写法一个都没有的句子不再分词（结果一样）；存 1.06 MB 的讲稿 3.8 秒（和上一版一样），说明每次刷新 0.01 秒。
  `r_perf.py` 原来每行带着换行符，「（第k遍）」单独成了一行、剩下的句子正好和程序自带的一样，现在会算成「程序里已经有」，改成去掉换行符再拼。
