# 全面找 bug（10-03，v18.5 发布前）

老师 10-03 的要求（原话）：「寻找一切可能出现的 bug，坚决不能有任何影响整个程序运行的 bug……必须保证任何我们做出来的功能
都能绝对完美的运行。互不冲突。坚决防止出现任何功能上的冲突。」

做法：分三轮找，每一轮找到的问题先**写复现脚本确认是真的**，修好以后**每个问题写一个测试，并且确认这个测试在修以前的代码上失败**
（证明测到了），最后整体再跑一遍所有测试、随机操作脚本、老师的真实数据和真实浏览器。

- 复现脚本都在 `复现脚本/`（`hunt/` = 第一、二轮，`sweep/` = 第三轮）。大多数用 `/tmp/gsv39/bin/python 脚本名.py` 运行
  （整合包同版本的环境：Python 3.9 + gradio 4.24 + pypinyin + jieba），不下载模型、不联网。
- 第三轮 6 路检查的报告原文（英文）：`检查报告原文_第三批.txt`。
- 测试：`tests/test_bug_hunt.py`（第一轮 6 个、第二轮 16 个、第三轮 17 个），另外 `tests/test_launcher.py`、`tests/test_installers.py`、
  `tests/test_webui_build.py`、`tests/test_proofcheck.py`、`tests/test_transcript_fix.py` 里也加 / 改了几个。

## 3. 第三轮：6 路全面检查 + 每条再找人核实（57 条）

6 路：功能冲突、升级、安装包、训练 / 生成、自动查错字、界面文字。每条先由另一个人独立复现（「核实」），再修。
核实时有几条已经被我修好了，所以核实结果写「不是问题」——下面按问题本身列，都修了。

### 3.1 自动查错字和一键校正互相冲突（最重要）

| 问题 | 怎么修 |
|---|---|
| 🔍 自动查找（加新素材时准备素材也会自动查）把一键校正的结果冲掉：没采用的建议没了、母本证明没错的标红又回来了（老师真实数据：50 句）、新查出来的藏在 `suspect_auto` 里看不到；按钮是灰的，找不回来 | 查完以后和一键校正的结果**合在一起**：一键校正处理过的行（记录里有的、标记是 `src=transcript` 的）把新结果当「自动查错字的结果」，调用 `check_with_transcript(only=…, merge_only=True)` 重新合并——**只合并，一个字都不改**（标准库能确定的也只当建议），也不算用了一次 |
| 老师撤销过的改法，🔍 以后又建议回来 | 查错字时去掉 `review_rejected.json` 里的改法，那几个字也不标红；一键校正合并时也一样（以前一键校正去掉建议但留着红字，两边不一致） |
| 「检查完了：N 条可能有错（已标红）」和表格上方的数字对不上（按保存的文字算、藏起来的也算） | 查完以后按表格显示的文字数（`review.analyze()["active"]`）；表格上方不算标了「不用」的；没找到时提示不再说「已经标红」 |
| 又改过、又可能有错的字：红色被蓝色盖住，看不到红字，也没有「这句没错」 | 一个字一个字算颜色，红色优先、下面加蓝线；「这句没错」按服务器给的标记（`vt-sus`）显示 |
| 老师常说的英文词（whose、why、he、way、she、my、one）被当成「把中文听成了英文」，还建议换成「户字」「外」「喜」「位」——老师改好的 1005 句里标红 50 句 | 老师母本里的英文词 + 素材里常出现的英文词（`proofcheck.english_vocab`）不走这条规则；第二个引擎的中文音译也就不会拼进建议。改完：1005 句里 0 句 |
| 删掉连着重复的一遍（定语从句定语从句 → 定语从句）以后，「重复了 2 遍」还标着 | 标红的是重复的那几遍、老师在这一串里改过，就算改过了（`review._repeat_fixed`） |
| 采用过的建议保存以后再 🔍，「已采用」的撤销按钮没了 | 有还能撤销的修改的行，标记留着 |

### 3.2 一键全部文字校正（每批素材只能用一次）

| 问题 | 怎么修 |
|---|---|
| 删除的、标了「不用」的句子被记成用过（以前算「这批素材」）：恢复 / 改成要用以后永远改不了 | 只记真的处理过的句子。恢复的、改成要用的句子还没改过，按钮亮、只改它们（每一句只改一次） |
| 没有拼音 / 分词工具（独立安装）：只改一点点，还用掉了唯一的一次 | 先说明、不开始，什么都不记；独立安装也装上这两个工具（`pyproject` 的 `webui`）；「检查环境」里多两行 |
| 表格里删除 / 恢复 / 保存 / 确认以后按钮不刷新 | 这几个操作以后刷新按钮、上传框、说明（`textfix_state`） |
| 按钮灰的时候不说为什么（还没识别出文字时，帮助里又说「灰色 = 用过了」） | 分开说：用过了 / 现在还没有能校正的句子；用过以后又亮了说「有 N 句还没用过」 |
| 用过以后上传母本没有任何反应（上传框还能用，文件也没存） | 按钮灰的时候上传框也灰；说明里写上传要等下次按钮亮的时候；上传框写「会替换上次上传的」 |
| 第二批只查了新加的几句，结果写「检查了 5 条」像出了问题；检查时又改过的句子不说 | 写「检查了新加的 N 条（以前改过的句子一点没动）」；说明有几条检查时又改过、按钮为什么还亮 |
| 「下载改好的文字」叫老师上传以后再点灰色的按钮；路径里多出反斜杠（`\_`） | 改成「以后按钮亮的时候也可以当母本上传」；路径原样显示 |
| 例子重复（一声 → 医生；一声 → 医生） | 去重 |
| 「撤销刚才的替换」：几天前（甚至旧版本）的替换记录还在，一键校正以后点它，把确认好的字改回去；已经改回去的句子还说「又改过」 | 确认训练素材、一键校正以后清掉记录；记录里带版本号，旧版本的不用；已经是替换前样子的句子不算 |

### 3.3 校对表其它

| 问题 | 怎么修 |
|---|---|
| 确认训练素材以后改了语言，不用重新确认（训练按新语言读） | 确认记录的指纹加上语言（`SIGNATURE_VERSION = 2`）；旧版本的确认记录按旧算法比，升级不用重新确认 |

| 勾着「只看可能有错的」查找：表格空着、状态说找到 15 处，「替换这一处」换掉看不见的句子 | 查找时不管「只看可能有错的」 |
| 确认过、但又有没保存的修改：表格上方只写「✅ 已确认」，点训练却被拦下 | 写「确认过，但后来又改了 N 条还没保存：保存以后再确认一次」 |

### 3.4 训练 / 生成

| 问题 | 怎么修 |
|---|---|
| 重新训练失败 / 中途停止：「现在的模型是用改之前的文字训练的」提醒消失（训练开始时就写了新素材的指纹） | 训练**做完**才把用的素材指纹记进 models.json（`list_sha1`），提醒按它算；旧版本训练的模型，下次训练开始前先把旧指纹记过去 |
| 同一分钟里先生成 WAV 再生成 MP3：刚听过的 WAV 被删掉（转 MP3 用的临时 WAV 就是同名的那个），字幕、报告也被覆盖 | 临时 WAV 用只有这次用的名字；同一分钟里重名的输出加 _2、_3 |
| 按字幕时间轴配音：两句能叠 20 毫秒、或者一点停顿都没有 | 不往回叠；句子之间至少 0.15 秒（逗号 0.08 秒）绝对静音 |
| 字幕时间写成 00:00:60,000（剪映不认） | 先换成整毫秒再拆 |
| MP3 停顿里不是绝对的 0（有损压缩，-93 dB，听不见），界面没说 | 选项上如实写明，要绝对静音选 WAV |
| 「训练以后又改过」的提醒只在折起来的「详细过程」里 | 也写进生成结果和挑选结果 |
| 训练记录「N 条是你改过的」把考试题、改了又改回去的也算进去 | 只数进训练的、和最初识别不一样的 |
| 讲稿里只有 ``` 代码 / [停顿] / 表情：说「讲稿是空的」，还生成问题报告 | 说清楚哪些不读；不生成问题报告 |

### 3.6 没有改的（为什么）

- **旧版本里撤销过的建议，一键校正不认得**（`review_rejected.json` 从 v18.5 才有）：想过从「文字 = 最初识别的、又改过」推断出撤销过，
  但老师自己打字改回去也是这样，推断错了会挡住正确的建议。一键校正改的都是没保存的修改，老师看一眼再保存，影响很小；记在教学手册。
- **MP3 做不到绝对静音**：有损压缩本来就会这样，只能如实写明。
