# 母本优先（10-04）：识别出来的句子先和母本对照，和母本不一样的地方就按母本改

## 1. 问题（老师的原话）

老师 10-04（北京时间）：

> 「识别出来的这些句子，先去跟母本对照。一般母本都会有差不多或者原模原样的句子。跟母本不一样的地方，那很明显就是错误的地方。
> 逻辑就这么简单。」
> 「这个自动检查错字功能，它的底层逻辑也是要以母本为主……母本是最优先级。」

老师在**和母本同一批讲课**的素材上点了「📝 一键全部文字校正」，很多句子、很多「修改建议」还是不跟母本走，
例如识别成「定于从句」、母本里是「定语从句」。

## 2. 原因（先在旧代码上量出来，`实测.py`，结果 `结果_旧代码.txt`）

用老师修缮以前的 1004 句（`../老师的母本/母本_原文.csv`）建声音，正确答案是修缮好的（`母本_修缮后.csv`，123 句不一样、138 处）。
三种情况：A 片段 id 和母本一模一样；B id 全都不一样；C id 不一样、而且切的位置不一样（83 处两句合成一句、106 处长句子在逗号处切开）。
另外放进「自动查错字」（第二个识别引擎，假的）和母本矛盾的建议：本来对的句子上 60 条（定语 → 定于、介词 → 借词……）、
有错的句子上 25 条（借词 → 接词……），40 条和母本一致；再加 40 句母本里没有的新内容。流程和老师一样：
自动查错字 → 一键校正 → 再点 🔍。

| 旧代码 | A（id 一样） | B（id 全变） | C（id 变 + 切法不一样） |
|---|---|---|---|
| 一键校正以后，和母本不一样的句子改得和母本一模一样 | 123 / 123 | **83** / 123（33 句没动、7 句改成别的样子） | **85** / 124（33 没动、6 别的样子） |
| 本来对的句子被改 | 0 | 0 | **2**（再 → which、whose → 只） |
| 一键校正以后还留着的、和母本矛盾的建议 | **33** 处 | 1 | 2 |
| 一键校正以前（准备素材以后的自动查错字）和母本矛盾的建议 | **43** 处 | 43 | 51 |
| 一键校正以前，点一下「采用」就和母本一样的句子 | 11 / 123 | 11 | 11 |

找到的原因（都核实过）：

1. **按片段 id 改**：138 处逐句修缮记录（`core_fixes.tsv`）按片段 id 记。片段 id 里有视频完整路径和大小算出来的编号
   （`data/prepare.py` 的 `source_id`）：重新准备素材、视频挪了地方、上传视频而不是选文件夹、升级以后新建了声音，id 就全变了，
   138 处一处都用不上（B、C）。剩下的「和母本对齐」很保守：要整句 ≥ 85% 对得上、前后各 ≥ 2 个一样的字才直接改，英文
   （let / dead → that、Tony Caesars → Tony's scissors）、多 / 少的字（翻译成文 → 翻译成中文）、句子开头结尾的错都改不了。
2. **id 一样时反而不拿母本里它自己那一句来比**（`check_text(exclude_id=...)`，原来是为了不让上传的 transcripts.csv「自己证明自己没错」），
   所以自动查错字和母本矛盾的建议（定语 → 定于）留着（A 的 33 处）。
3. **自动查错字（准备素材以后 / 🔍）根本不看母本**：建议只来自第二个识别引擎和规则；只有一键校正处理过的行才和母本合一次。

## 3. 怎么改

新文件 `voicetwin/data/mother_first.py`，接到 `transcript_fix.check_with_transcript`（一键校正和自动查错字合并都走它）：

1. **按内容找，不按 id**。母本（程序自带的修缮好的 1005 句 + 老师上传的）当成一整串话（标点不算），每个字换成模糊读音
   （zh/z、n/l、ang/an 不分，英文用读音代码，和原来的对齐用同一套），三个音一组找候选位置；这一句和候选那一段按读音对齐，
   挑「对上的多、中间空的少」的一串当范围；句子第一个 / 最后一个字和母本挨着的字一样、中间只隔 1~3 个对不上的字时从它算起
   （被按的连接 / 被and连接）；开头结尾对不上的 1~3 个字读音像（同声母 / 同韵母、汉字读音像英文）时算听错了。
   id 只当**提示**：同一个 id 的那一句文字也对得上（相似度到门槛、和最像的差不到 0.02）才优先用它；同一个 id 时母本那一句只多出
   开头 / 结尾 1~3 个字（「……句子。」/「……句子吧。」）才补上，不是同一个 id 的不补（可能只是切的位置不一样）。
2. **相似度** = 读音对上的字数 ÷ max(这一句的字数, 母本那一段的字数)。「找到了」要同时满足：
   - 相似度 ≥ **0.85**（`MATCH_MIN`，见第 4 节怎么量出来的）、至少 4 个字 / 词；
   - 整句都对上（开头 / 结尾没对上的只能是「嗯、啊」这种语气词），**或者**对上的正好是母本里完整的一句（几句）、至少 10 个字 / 词
     （两句合成一句、其中一句是新的话）。只对上一句中间的一小段不算（「我们来看一下」这种常说的话到处都有）。
   - 排序按「对整句来说有多像」，整句对上的排在一小段一模一样的前面；差不多一样像时程序自带（修缮过）的母本优先；
     好几处一样像、写法又不一样（分不出是哪一处）时这一段不按母本改。
3. **找到了，母本就是标准答案**：对上的那一段按字和母本比（英文按整个单词），读音一样写法不一样的（定于 → 定语）、读音不一样的
   （let → that）、多的、少的、英文大小写都按母本；对上的正好是母本一句的开头 / 结尾时句首句末的标点也按母本；只是写法整理
   （全角 / 半角逗号）不一样的不算。一处大的改动再按读音拆细（「从具的 → 从句」拆成「具 → 句」和删掉「的」），
   这样老师自己加的字不动、旁边该改的照样改。
   - 一键校正里直接改（存成没保存的修改，红灯），说明写「已按母本改好：定于从句 → 定语从句」；
   - 自动查错字（准备素材以后、🔍）以后**每一句都先和母本对照**（`proofcheck.find_suspects` 查完调用
     `check_with_transcript(merge_only=True)`，以前只对一键校正处理过的行），不改字，按母本的建议算有把握，「修改建议」那一列写
     「**按母本：**……」、排在最前面；和母本矛盾的另一个引擎的建议、标红都去掉（说明也去掉）。
   - 母本里没有的部分才用逐句修缮记录（按 id）、对照表、术语、和母本里别的句子局部对齐、另一个识别引擎和规则。
   - 局部对上时「汉字可能是英文」的猜测：那几个汉字本身是正常的词（jieba 词典里 ≥ 100 次，出错 156）不提示
     （以前新内容里的「出错」被猜成 whose）。
4. **原来的规矩照旧**：
   - 老师自己打的字**一律不动**（和最初识别的文字比，`_changed_chars` / `_protect`）；和母本不一样时点那一行看得到一句说明
     「母本里这里是「和介词一」，现在是「和介绍词一」（你改过这里，或者以前采用过别的修改）：程序没有动（你的修改为准……）」（`record["mother_note"]`，
     只在文字还是那时候的样子时显示）。
   - 删除的行、不用的行、点过「这句没错」的行不动；一键校正每批素材只能用一次。
   - **老师撤销过的改法（`review_rejected.json`）照样不再改、不再建议，母本说的也一样**——决定：老师听了录音、亲手撤销，
     说明这一句录音里就是这么说的（比如这次讲的时候换了个说法），老师的决定比母本更可靠；再按母本改回去就会和老师来回拉锯。
     点那一行看得到说明「母本里这里是……，这个改法你撤销过：程序没有再改」。
   - **只有程序自带的、老师修缮过的母本「说了算」**（`core_corpus.tsv`，老师说的「母本」）。老师上传的文字没修缮过，
     可能是讲课以前写的讲稿（讲的时候换说法很正常），也可能有拼音输入法打的同音错字（「主雨」）：只在读音像识别错的地方
     （读音一样的字、汉字读音像英文、英文拼法很像）按它改，读音一样的单个字只给没把握的建议，改完以后标准库马上又会说错的不改；
     多出来的、少了的、读音不一样的说法不按它改，标准库照样查整句，自动查错字的结果照样留着（见 5.1½ 的实测）。
   - 指纹（`suspect["fp"]`）里加了母本优先的版本号、门槛、是不是只合并：升级以后、自动查错字以后再点一键校正都会按新的做法重新算。
5. 网页：`TEXTFIX_HELP`、校对表说明、「修改建议」的说明、一键校正的结果（「母本最优先：在你的母本里找到了差不多的句子 N 条」）、
   点一行时的对比（全是按母本的才写「按母本改成」，不然写「建议改成」）；《快速上手》第 6½ 步和 PDF（还是 8 页）。

## 4. 门槛怎么定的（`分布.py`，结果 `分布结果.txt`）

在老师的母本上量相似度的分布：

| 量的是什么 | 结果 |
|---|---|
| 同一句：修缮以前的 123 句在程序自带的母本里找（里面有它自己） | 最低 **0.867**（0.85~0.9：1 句，0.9~0.95：12 句，≥ 0.95：110 句）；按找到的那一段改完 **123 / 123** 和修缮好的一模一样；本来对的 881 句一句都不改 |
| 新的话：母本里每一句（修缮好的）拿掉它自己再找，看会不会被别的句子硬改（老师讲课会重复差不多的话，这一项最能说明门槛够不够高） | 1005 句里能当成「找到了」的：门槛 0.80 时 12 句（其中会被改的 11 句），**0.85 时 2 句（会被改的 1 句）**，0.90 时也是 1 句。别的句子最像的最高 **0.842**（「如果我们把这个定语从句也翻译成中文呢？」对上另一句，会被加字删字） |
| 那 1 句 | 「会想得非常不自然。」（`and-revised_db6f95_0030`，母本里标着「太短」、不用来训练，所以修缮时没改到）对上另一句的「会显得非常不自然」，被改成「显得」——**这正是母本里漏改的识别错**（上下文是「and 将北京和深圳连接成了一个整体。会显得非常不自然。」）。请老师确认以后可以把母本这一句改成「显得」 |
| 修缮以前有错的 123 句拿掉它自己再找 | 到门槛的 0 句（母本里没有它自己时，别的句子帮不上忙，交给标准库，和以前一样） |
| 自己写的 40 句新内容 | 最像的都到不了门槛（0 句） |

所以门槛取在两堆中间：**0.85**（同一句最低 0.867，别的句子最高 0.842）。间隔不大（0.025），如实说明：
如果以后老师讲的新句子和母本里某一句只差一两个字（一共十几个字），程序会当成同一句、按母本改——这正是老师说的规则
（「跟母本不一样的地方就是错误」）；在老师现在的 1005 句里这种情况只有上面那 1 处，而且那一处是母本自己错了。

开发中改过的：只对上一部分时最少的字数从 8 改成 **10**：8 的时候上面那句 8 个字的「会想得非常不自然」被当成别的长句子的一部分，
把对的「显得」改成「想得」（`老师母本实测.py` 的「考试」里也看到了这 1 处），10 以后没有了。

- 4 个测试原来用母本里的句子、配上和母本矛盾的自动建议（像主语 → 了、补上「那个」「which」「的」），测采用 / 撤销 / 连点两次的
  细节——母本优先以后这些建议直接不要了，测不到原来的细节 → 换成母本里没有的新句子（同样的错字、同样的建议），细节照样测；
- 2 个「上传下载的改好的文字不能自己证明自己没错」：原来的句子母本里有，母本本来就证明了 → 换成新句子；
- 「英文不被换成读音不像的汉字」：原来那几句是母本里的句子改了一两个词，现在按母本改回去 → 改成检查「要么不动、要么是母本里
  那一句的原样，英文词不会变成汉字」；
- 说明文字（「已按母本改好」）、🔍 合并时进度条上的字（「和你的母本对照」）、存进校对表的标记（多了 text / src，没有原因的位置）。

## 6. 淘汰的做法

| 做法 | 为什么不用 |
|---|---|
| 按片段 id 用逐句修缮记录（原来的主要办法） | id 里有视频路径和大小，重新准备 / 换文件夹 / 新建声音以后全变，138 处一处都用不上（旧代码 B：123 句只改对 83 句）→ 按内容找；id 只当提示 |
| 只对上一小段（≥ 8 个字）也算找到、在那一段里按母本改（开发中的第一版） | 母本里每一句拿掉它自己再找：门槛 0.80 时 41 句会被别的句子硬改（常说的话、同一个意思换个说法）→ 只认整句对上、或者正好是母本里完整的一句 |
| 按相似度排候选 | 一小段一模一样的常说的话（相似度 1.0）把整句对上的（0.97）挤掉，整句反而没找到 → 按「对整句来说有多像」排 |
| 门槛 0.80 | 母本里每一句拿掉它自己再找，12 句会被当成找到了（11 句会被改）→ 0.85（2 句 / 1 句，那 1 句是母本自己漏改的） |
| 只对上一部分时最少 8 个字 | 8 个字的「会想得非常不自然」（母本漏改的）把别的句子里对的「显得」改成「想得」→ 10 |
| 按读音对齐出来的位置一个字一个字改 | 标点（Where is quiet? / where it's quiet.）、英文大小写（Let Man / That man）改不到，123 句里 4 句改不全 → 整段按字比，再按读音拆细 |
| 句子开头 / 结尾没对上的字一律算母本挨着的字（不看读音） | 「被按的连接」被改成「and连接」（把「被」也换掉了）→ 先看第一个 / 最后一个字是不是一样，再看读音像不像 |
| 母本那一句比这一句多出来的开头 / 结尾都补上 | 一句切成两句时，会把另一半补进来（录音里没有）→ 只有同一个 id、只多 1~3 个字时才补 |
| 老师上传的 transcripts.csv 里同一个 id 的那一句不拿来比（交给原来的「同一个 id」规则） | 那一句不能比，就对到上传的别的句子上硬改（「我们来看一下这个句子」被改成「……这个例子」）→ 当提示用，老师改过的字照样不动 |
| 老师上传的文字也「说了算」（和程序自带的母本一样） | 上传的可能是讲稿：45 句里 7 句实际说的话被改成讲稿写法、3 句对的被改，还因为一部分改了一部分没改出现「装语从句」这种乱字（`讲稿实测.py`）→ 只有修缮过的母本说了算，上传的只按读音像识别错的地方改 |
| 母本说了算的地方，老师撤销过的也改回去 | 老师听了录音亲手撤销的，说明录音里就是这么说的；改回去会来回拉锯 → 撤销的照样不动，点那一行看得到说明 |
| 自动查错字只和一键校正处理过的行合并 | 准备素材以后、点一键校正以前的建议都不看母本（旧代码：和母本矛盾的 43 处）→ 每一句都先和母本对照 |
| 把母本里漏改的「会想得非常不自然」直接改掉 | 母本是老师的，改母本要老师同意（而且会改动「138 处」这些记录过的数字）→ 记在这里，请老师确认 |
