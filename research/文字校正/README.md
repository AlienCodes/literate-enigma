   「借词这种词是不可能出现的，正确的是介词；艾子也不可能出现，正确的是 as」。

   谓语、宾语、表语、名词性从句、状语从句、形容词词性、虚拟从句……）」；「修缮后的母本就是我所有的说话习惯，

## 2. 母本的修缮（逐句人工读完 1008 句）

老师的 `transcripts.csv`：1008 句（删除的 3 句、太短的 1 句），约 5.2 万字，讲的是英语语法（定语从句、关系代词、
关系副词、从句的本质、连词和并列句……）。里面还有老师没看到的识别错误（借词 17 处、关系带词 6 处……）。

- 先用程序按读音找（同一个读音的不同写法、少数的那种算错）：找出 682 个候选，误报很多（「词一」是「介词一起」、
  「道这个句」是「知道 / 引导」、「原型」是老师的习惯说法……）→ **不能只靠程序**。
- 所以把 1008 句**逐句读了一遍**，只改明显的识别错误（读音一样或很像的别字、被写成汉字或写错的英文、少了的字），
  不改老师的说法和措辞：**138 处**（123 句），见 [`老师的母本/修缮记录.tsv`](老师的母本/修缮记录.tsv)。
  另外 6 处英文例句听不出原话，没有改，列在 [`老师的母本/请老师听一下.tsv`](老师的母本/请老师听一下.tsv)。
- 改完再用程序扫一遍：剩下的候选全是误报（跨在两个词中间、或者老师自己的说法），说明术语类的错都改干净了。
- 文件：[`老师的母本/母本_原文.csv`](老师的母本/母本_原文.csv)、[`老师的母本/母本_修缮后.csv`](老师的母本/母本_修缮后.csv)
  （只有 id 和文字，没有录音路径；老师 10-03 明确同意公开）。

改掉的错误种类（举例）：借词 → 介词、关系带词 → 关系代词、定语从剧 / 从具 / 从据 → 定语从句、主位结构 → 主谓结构、
叙述词 → 序数词、现行词 / 进行词 / 线性词 → 先行词、不纠动词 / 不修动词 → 不及物动词、同类向 → 同类项、
位置 / 未知 → which、问 → when、闹 → nor、按的 → and、dead / let / NET → that、述之 → 树枝。

## 4. 怎么改（`voicetwin/data/lexicon_fix.py`、`voicetwin/data/transcript_fix.py`）

每一处都必须「刚好是一个完整的词」：用 jieba 分词（GPT-SoVITS 整合包里有 jieba 和 jieba_fast）判断，
「凭借词汇」里的「借词」、「介词一起」里的「词一」、「同位语」里的「位语」都不算。

| 来源 | 改法 |
|---|---|
| 逐句修缮记录（同一个句子 id） | 这一句和母本里同一个 id 的句子至少 60% 一样（是同一句）、那几个字还在 → 直接改 |
| 老师上传的 transcripts.csv（同一个 id） | 老师**没改过**的句子：≥ 80% 一样直接改、50% ~ 80% 给建议、更少不是同一句不用；老师自己改过的句子（保存的、没保存的）**不用**，不建议改回去 |
| 对照表 | 直接改（没有 jieba、判断不了是不是完整的词时只给没把握的建议） |
| 读音和术语 / 母本常说的词一样，写法不一样 | 至少一半的字相同、这种写法在母本里几乎没出现（≤ 正确写法的 1/3）、不是常用词（「一声」「以下」）：读音完全一样、而且写成了「不是词」的样子（定语从剧）的直接改；本身是一个词的（壮语、原籍、定于）和声调不同的只给没把握的建议 |
| 和母本里的句子按读音对齐（pypinyin 拼音 + 模糊音，英文用读音代码） | 整句几乎一样（≥ 85% 的字对得上、前后各 ≥ 2 个一样的字）直接改；别的只给建议，而且再筛一遍：术语里的字不动、只差一个字的不提示、本来就是常用词的「英文被写成汉字」不提示；汉字被写成英文（the → 的）必须读音像 |

「一键全部文字校正」= 上面直接改的 + 「修改建议」那一列**有把握**的建议一次全部采用。有把握 = 经过文字校正检查、分量 ≥ 0.8
（或者另一个识别引擎也听成这样）；自动查错字原来的建议只认标准库能证明的（不是常用词的汉字、读音像英文：艾子 / 威驰 → as / which）。
**没把握的不自动改**（两个引擎听得不一样的中文、整句都不一样的、本身是词的同音字……），还是红色、建议还在，
老师听录音，对就点那一行的蓝色的「采用」；结果说明里写着有几条。
改的都存成**没保存的修改**（红灯）：改过的字「文字」列绿色、「可能有错」列蓝色，「修改建议」的按钮变红（点一下撤销，
以前采用过的建议再点一次一键校正以后也能撤销）；只标红、没有建议的地方还是红色。老师点「保存修改」确认，训练前点「确认训练素材」
（没保存不能训练，v18.4 起就是这样）。删除的行、不保留的行、点过「这句没错」的行（按表格里显示的那句记）都不动。

母本证明没错的地方，原来自动查错字的标红会去掉——但只算「整句几乎一样」的；局部对上「这个句子」这种常说的话
不能证明录音里就是这么说的（开发中发现原来的规则太松，改掉了）。

## 5. 实测

**老师真实的 1004 句**（[`老师母本实测.py`](老师母本实测.py)，结果 [`老师母本实测结果.txt`](老师母本实测结果.txt)）：

| | 结果 |
|---|---|
| 正常用法（一键全部文字校正） | 需要改的 123 句**全部改得和逐句修缮一模一样**；138 处全部找到；**多改 0 处**；用时约 6 秒 |
| 正常用法 + 老师又上传了修缮以前的 transcripts.csv（同样的 id，里面还有「借词」） | 结果一样：123 句全对、多改 0 处、剩下标红 0 句（有测试） |
| 考试：不用逐句修缮记录，只靠标准库 | 找到 70 / 138 处，**改错 0 处**；只给没把握的建议 1 句（「关系dex」→「关系代词」，建议是对的）。没找到的多是英文（let / dead → that）和个别说法。比第一版少 4 处：对照表去掉了正常话里也会出现的 4 种写法（见第 5¾ 节），这 4 句在正常用法里照样按逐句修缮记录改好。注意对照表是从这次修缮里总结的，所以对以后的新录音偏乐观 |

**自己写的评测数据**（[`评测.py`](评测.py)，只测「和母本对齐」这一部分）：同一节课的讲稿 31 / 32 处找到（没找到的是按设计不标的
他 / 它）、平时习惯 8 / 10 处（没找到的两处是逐字稿里根本没有的英文词）、没有错误的句子误报 0；4.6 万字母本 + 1000 句约 2 秒。

**做不到的**（如实告诉老师）：录音里说的和母本、术语都对不上的错字（比如一个新的、母本里没有的词被听错），程序没法知道正确写法，
只能靠自动查错字标红、老师听录音改。不能保证 100%。

## 5½. 真实浏览器实测（gradio 4.24 + Python 3.9 + pypinyin + jieba，和整合包同版本）

`research/过程文件/04_浏览器实测/m29_v18.5一键文字校正/`：用老师修缮前的 1004 句建一个声音，在网页上点一遍。最后一次 **19 / 19 通过**
（`check_结果.txt`）：按钮和标准库说明、123 句全部改对、自动查错字的建议一起采用、绿 / 蓝 / 红灯、浏览器自动下载 txt、
保存修改 → 确认训练素材 → 训练列表里是改好的字、上传 txt 母本再点一次、改好保存过的句子不会再被改、网页没有脚本错误。

实测中发现并修好的两个真问题：
1. 「下载」后面自动点下载链接的网页脚本没有返回列表 → gradio 4.24 报错，之后「保存修改」等按钮点了都没反应。
2. **从老师保存的修改里学到了「位置 → which」「按照 → and」**（修缮时个别句子里它们确实是英文被写成了汉字），
   第二次点一键校正时把别的句子里正常的「位置」「按照」也改掉了。→ 老师改过的错，错的写法在母本里出现过、或者是常用词，就不学；
   加了测试：改好、保存以后再点一次，什么都不改。（后来发布前检查又发现学到程序自己改的，干脆不学了，见第 5¾ 节。）
（另外两次失败是测试数据的问题：录音是静音、少了 source 字段 → 换成合成的人声、补上字段；程序里缺 source 时也不再报错。）

## 6. 淘汰的做法

| 做法 | 为什么不用 |
|---|---|
| 逐字硬对逐字稿 | 老师说逐字稿只是说话习惯，不一样的地方大多是老师当时换了说法 |
| 「同音不同写、少数的算错」直接用在所有词上 | 682 个候选，误报很多（跨词、老师自己的说法），见第 2 节 |
| 用 pypinyin 的词典判断「是不是一个词」 | 它只收多音字相关的 4.7 万个词，「介词」「先行词」都不在里面 → 改用 jieba 的 35 万词词典 |
| 局部对上 4 个字就算「母本证明没错」 | 常说的话（这个句子）到处都有，会把自动查错字的真问题去掉 |
| 对齐到母本里别的相似句子时也直接改 | 实测出 12 条误报建议（及物动词里的「及」、「示 / 是」），改成只有整句几乎一样才直接改，其余再筛 |
| 母本只放在老师电脑上 | 老师要求放进仓库当标准（10-03 明确同意公开） |
| 老师改过的错一律学 | 「位置 → which」这种只在个别句子里对的改法会到处乱改（浏览器实测发现）；后来改成只学母本里没出现过、也不是常用词的错写法 |
| 从校对表里学老师改过的错（筛过的也不行） | 保存的修改里也有程序自己改的、老师采用的建议（李华 → 理化），学进去会把错的改法扩散到别的句子（发布前检查发现）；不再学 |
| 一键校正把「修改建议」全部采用 | 自动查错字的建议是另一个识别引擎的猜测，两个引擎听得不一样的中文不知道哪个对；全部采用会把错字写进训练素材。改成只采用有把握的，没把握的留着红色让老师听 |
| 按位置记哪一处建议没把握（`suspect["unsure"]` 位置） | 同样的字挨着时两次比对的位置会差一个字，没把握的混进来（第二次检查发现）→ 记「只用有把握的改出来的那一句」 |
| 对齐到母本的句子就直接改（不管这几个字改没改过） | 母本里旧的写法会把改好的、老师自己改的字改回去（第二次检查发现）→ 改过的字不动 |
| 撤销记「前后 3 个字」（第二次检查后的做法） | 挨着的两处、一次改好几处、重复的句子对不上，老师真实数据 12 句又改回来（第三次检查发现）→ 按单位记「原来的 → 想改成的」 |
| 撤销记录存在校对表（manifest）里 | 自动查错字 / 准备素材保存校对表时会冲掉 → 单独的 `review_rejected.json` |
| 靠「可能有错」列的记录判断老师是不是把采用的建议改回去了 | 句子开头 / 结尾、删掉的字认不出来；点过「这句没错」、重新查过错字以后记录没了（第四次检查发现）→ 和最初识别的文字比 |
| 「撤销刚才的替换」把撤销记录整个恢复成替换以前的样子 | 会把老师在替换以后的撤销也去掉（随机操作脚本发现）→ 只去掉替换自己加的 |
| 采用 / 撤销时按「查错字时的文字 → 建议」一个字一个字对位置 | 同样的字挨着时会配错，把文字改坏（第五次检查发现「了、宾语、宾语」）→ 记下几个整句，正好是其中一个时整句换 |
| 采用 / 撤销对不上整句时，按「查错字时 → 都改好」两头算哪些采用过 | 挨着的两个建议一个采用了、一个没采用时会连成一处，撤销时把字改乱（随机操作发现「关系系带词」）→ 从改动最少的那一句算 |
| 对不上整句时一处一处改，改完要求「改回去又正好是原来的」 | 太严：老师已经自己打了建议里的一处时，采用只改一部分（随机操作发现）→ 三方合并，两边同一处一样算一处，碰到一起就不改 |
| 一键校正改出来的文字保留母本里的全角逗号（as，） | 表格里别的文字（老师打的、点采用的）都整理成半角（as,），整句对不上 → 都整理成表格的写法 |
