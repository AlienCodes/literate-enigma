第 10 章讲稿的写法与读音控制

同一个模型，讲稿写得好不好，生成出来的效果差别很大。这一章告诉你：程序是怎么"读"你的讲稿的、怎样控制停顿、怎样纠正读错的字，以及怎样写出"听起来像你在讲"的讲稿。

10.1 支持的讲稿格式

格式怎么得到说明
.txt 纯文本记事本、WPS 另存为"纯文本"最推荐，最不容易出问题。UTF-8、GBK（记事本默认的"ANSI"）编码都能自动识别。
.md MarkdownTypora、Obsidian、VS Code 等标题、列表、加粗、链接等格式会被自动清理，只读文字（10.5 节）。
.docx Word 文档Word、WPS 文字按段落读取。表格、图片、批注、页眉页脚不会被读出来。老版 .doc 格式不支持，请另存为 .docx 或 .txt。
.srt / .vtt 字幕剪映等软件导出按字幕的时间轴生成，每一句放在字幕对应的时间点上（10.7 节）。
直接粘贴网页里的 讲稿 文本框适合短内容。粘贴后的效果和 .txt 一样。
长讲稿推荐用 .txt 或 .md 文件上传：方便保存。上传后文件内容会放进讲稿框，可以直接在网页里修改；改完再生成时，程序只会重新生成改动过的句子（9.5 节）。

10.2 程序是怎么把讲稿切成句子的

模型一次只能读一小段话，所以程序会先把讲稿切成一句一句，逐句生成，再按你本人的停顿习惯拼接起来。切分规则如下，了解它能帮你写出更顺的讲稿：

规则具体做法
按句末标点切句遇到 。！？；… 和英文的 . ! ? ; 切开。英文里的小数（3.14）、缩写（Mr. / e.g. / etc.）不会被误切。
换行 = 句子结束一行结束、而行尾没有标点时，会被当作一句话结束（自动补上句号）。行尾是逗号、顿号等标点时，下一行接着读，不会断句；英文句子在单词中间被硬换行（下一行以小写字母开头）时也会自动接回去。
空一行 = 分段段与段之间用你本人的段落停顿（通常 1 秒左右），段内句子之间用句子停顿。
太短的句子会合并少于 6 个字（音节）的句子，例如"好。""对吧？"，会和下一句合在一起生成，避免孤零零的一两个字听起来生硬。
太长的句子会拆开中文超过 50 个字、英文超过约 45 个音节的句子，会在逗号、顿号等处拆成几段生成，中间用很短的逗号停顿连接，听起来仍然是一句话。
句子的语气类型以问号结尾的是疑问句，以感叹号结尾的是感叹句，其它是陈述句。程序会给不同类型的句子挑不同语气的参考音频（13.2 节）。
为什么停顿会像我？第 6 章准备素材时，程序已经从你的录音里统计出了你的停顿习惯（逗号处停多久、句号处停多久、换段落停多久），生成时就按这个习惯决定每个停顿的长短，并且长短每次略有变化，不会像机器一样整齐划一。停顿里面是完全的静音：没有背景声、没有底噪，成品里只有你的声音。

10.3 停顿标记：想在哪儿停，停多久

除了标点和空行，你还可以在讲稿里直接写停顿标记，精确控制停顿。标记本身不会被读出来，也不会出现在字幕里。

写法效果例子
[停顿] 或 [暂停]段落停顿（按你的习惯，约 1 秒）我们先看第一个例子。[停顿]
[pause] 或 [break]同上（英文写法）Let's move on. [pause]
[停顿=2]停 2 秒大家先想一想。[停顿=2]
[停顿=1.5]停 1.5 秒可以写小数
[停顿 3秒] 或 [停顿：3]停 3 秒等号、冒号、空格都可以
[停顿=800毫秒]停 0.8 秒用毫秒更精确
[pause=800ms] / [pause=2s]停 0.8 秒 / 2 秒英文单位 ms、s
<break time="800ms"/>停 0.8 秒兼容其它配音软件的 SSML 写法
  • 停顿标记要写在句子后面：它会替换掉这句话后面原本的停顿。
  • 方括号用中文输入法的 【】 不行，必须是英文的 [ ]；里面的"停顿"两个字不能写错。
  • 写在讲稿最开头的停顿标记会被忽略（音频开头本来就有一小段静音）。
  • 停顿标记产生的停顿和其它停顿一样，都是完全的静音。
录屏课程的好帮手讲到"大家看屏幕上这段代码"时，后面加一个 [停顿=3]，就能留出 3 秒让画面演示，剪辑时对齐轻松很多（第 11 章）。

10.4 读音纠正词典：解决读错字、多音字、专业术语

模型偶尔会读错多音字（"行长"读成 xíng zhǎng）、专业术语或英文缩写（"SQL"该读 sequel 还是 S-Q-L）。遇到这种情况，把正确读法写进读音纠正词典，以后所有讲稿都会自动按你的读法来读，字幕里仍然显示原文。

  1. 打开文件夹 D:\VoiceTwin\workspace\我的声音，找到 lexicon.txt（第一次准备素材后自动创建）。
  2. 在文件上点右键 → 打开方式 → 记事本。
  3. 文件开头有几行以 # 开头的说明和例子（# 开头的行不会生效）。在文件末尾，每行写一条：原文 => 实际朗读的文字。 
    # 读音纠正词典：每行一条，格式为  原文 => 实际朗读的文字
SQL => sequel
GPT => G P T
Python3 => Python 三
行长 => 航长
重庆 => 虫庆
≥ => 大于等于
e.g. => for example
API => A P I
  4. 按 Ctrl+S 保存。如果记事本询问编码，选 UTF-8。
  5. 回到网页重新点 生成。包含这些词的句子会用新读法重新生成，其它句子直接用缓存，很快。
想解决的问题词典写法说明
多音字读错行长 => 航长用同音、不会读错的字代替。要写成词（两个字以上），不要只写一个字，否则会把所有"行"都换掉。
英文缩写要一个字母一个字母读GPT => G P T字母之间加空格。
英文缩写要读成单词SQL => sequel写成你平时的读法。
符号、公式≥ => 大于等于模型不认识的符号可能被跳过，写成文字最稳。
你习惯的特殊叫法for 循环 => four 循环按你讲课时实际怎么说来写。
版本号、型号v2.0 => 二点零版本避免被读成奇怪的数字。
词典的匹配规则 ① 长的词条优先：同时有 Python 和 Python3 时，先替换 Python3。 ② 纯英文 / 数字的词条按整个单词匹配：API => A P I 不会把 RAPID 里的 API 换掉。 ③ 中文词条是直接查找替换，所以要写得足够长、足够具体。 ④ 词典对这个声音的所有讲稿都生效。
词典只改变"送去读的文字"，不能改变模型的发音方式。如果某个词用各种写法都读不对，试试换一种说法（改讲稿），或者在它前后加逗号，让它单独成为一个短语。

10.5 用 Markdown 写讲稿

如果你习惯用 Markdown 写课件，可以直接上传 .md 文件。程序会按下面的规则处理：

Markdown 写法程序怎么处理

**重点**、*斜体*、`代码`去掉符号，只读文字。
[链接文字](网址)只读"链接文字"，网址不读。

表格每一行的各个格子用逗号连起来读（表格分隔线不读）。一般建议把表格改写成口语。
``` 代码块 ```默认整块不读（程序代码念出来没有意义）。想读代码块，把设置里的 skip_code_blocks 改成 false（13.3 节）。

10.6 数字、符号和中英混读

  • 数字范围：3~5 会读成"3 到 5"（英文句子里读成 "3 to 5"）。
  • 破折号：—— 会变成一个逗号停顿。
  • 各种括号（【】《》[] {} <>）：括号符号本身不读，里面的文字照常读。书名号里的内容照常读。
  • 普通数字、日期、百分比：一般能正确读出。但电话号码、编号、版本号、代码、数学公式等建议写成你想读的样子，例如把 x^2 写成"x 的平方"，把 1/3 写成"三分之一"。
  • 中文里夹英文单词：直接写即可，例如"我们用 Python 的 list 来存数据"。英文单词前后加不加空格都可以。
  • 整句英文：会自动识别为英文句子，用你的英文参考音频、英文语速来读。一段话里中英文句子可以交替出现。
拿不准的读法，先用"快速"档生成试听一遍（几秒钟一句），把读错的词记下来统一写进词典，再用"完美"档正式生成。

10.7 按字幕时间轴生成（给现成的视频重新配音）

如果你有一个视频和它的字幕文件（.srt），想用你的新声音把它重新配一遍，并且让每句话还出现在原来的时间点，可以直接把 .srt 文件作为讲稿上传：

  1. 在剪映等软件里给视频生成字幕，检查、修改好字幕文字，导出为 .srt 文件。
  2. 在 ③ 生成讲课音频 的 或上传讲稿文件（txt / docx / md / srt） 里上传这个 .srt 文件。页面会提示"已载入字幕文件……会按字幕的时间轴生成"。
  3. 点 生成。每一条字幕会被读出来，并放在这条字幕的开始时间上。
  4. 生成的音频长度和原视频对得上，可以直接替换原视频的声音（11.3 节）。
如果提示"第 N 句比字幕时间轴晚了 X 秒"说明上一条字幕的文字太多、而它的时间段太短，你的语速读不完，后面的句子只能顺延。解决方法：精简上一条字幕的文字，或者在剪辑软件里把那一段画面放慢一点；也可以把 语速 拉杆稍微往左拉（例如 −5，就是快 5%）。
按字幕生成时，句子之间的停顿由字幕时间决定，讲稿里的 [停顿] 标记和"空行分段"规则不适用。

10.8 写出"像你在讲"的讲稿：12 条技巧

  1. 用说话的方式写，不用书面语。"咱们来看一下这个例子"比"下面展示一个示例"更像讲课。
  2. 多用短句。一句话最好不超过 30 个字。长句子容易读得平、读得急。
  3. 标点要准确。问句一定用问号，模型会用提问的语气；感叹句用感叹号；该停的地方加逗号。
  4. 保留你的口头习惯。如果你平时爱说"那么""对吧""好，"，适当写进讲稿，会更像你。但不要每句都加。
  5. 不要用省略号代替停顿。想停顿请用逗号、句号或 [停顿=1]。
  6. 避免大段括号注释。括号里的话读出来很突兀，改成"也就是说……"之类的口语。
  7. 数字、符号写成读法（10.6 节）。
  8. 一个意思一段。用空行分段，段落停顿会让听众有"换气"的感觉。
  9. 重要的话单独成句。"注意，这一点非常重要。"单独一句，比埋在长句子里效果好。
  10. 中英文切换不要太频繁。一句话里夹一两个英文术语没问题；中英文整句交替时，最好一段内保持同一种语言。
  11. 和你的训练素材风格一致。模型最擅长模仿你讲课的样子；用它念诗、演戏、喊口号效果会差很多。
  12. 先试听再定稿。写完先用"快速"档听一遍，把拗口的句子改顺。

10.9 一份完整的示例讲稿

下面这份讲稿用到了本章的大部分写法，你可以复制到网页里试一试：

# 第四课：生成器表达式

同学们好，欢迎回来。上节课我们学习了列表推导式，今天我们来学习一个和它非常相似、
但是更节省内存的写法，叫做生成器表达式。

先想一个问题：如果我们要处理一个有一千万行的文件，把它全部读进列表里，会发生什么？[停顿=1.5]

对，内存很可能就不够用了。生成器表达式就是为了解决这个问题。

我们看屏幕上的这段代码。[停顿=3]

它和列表推导式的写法几乎一样，只是把方括号换成了圆括号。注意，这一点非常重要！

Today, let's also look at the English term. It's called a generator expression.

好，今天的内容就到这里，大家辛苦了！
这份讲稿会被切成 12 句：标题 1 句；第一段 2 句（第一段第一行行尾是顿号，所以和第二行连成一句）；提问句用疑问语气，读完停 1.5 秒；"我们看屏幕上的这段代码。"后停 3 秒；"注意，这一点非常重要！"用感叹语气；两句英文用英文参考音频和英文语速；最后一句用感叹语气结尾。

第 11 章把生成的音频用到课程视频里

生成的音频（.wav）和字幕（.srt）可以直接导入任何剪辑软件。这一章以最常用的剪映（电脑版 / 专业版）为例，介绍几种常见的用法；也介绍一个不用剪辑软件、一条命令替换视频声音的方法。

11.1 四种常见用法

A. 录屏 + 新配音

先写讲稿、生成音频，再对着音频录屏或做 PPT 动画。最推荐：嗓子不用出力，画面跟着声音走。

B. 给旧视频换声音

原视频声音质量差（嗓子哑、有杂音），用字幕时间轴重新生成（10.7 节），再替换原音轨（11.3 节）。

C. 补录、修改某一段

视频里某句话讲错了，只生成这一句，剪进去替换掉。音色、音量都接近你本人；剪好后自己先仔细听一遍衔接处（12.5 节）。

D. 纯音频课程

音频课、播客式课程：直接把生成的音频上传到课程平台（③ 页面的"保存格式"可以选 MP3，9.2 节）。

11.2 在剪映里使用生成的音频和字幕

  1. 打开剪映，点 开始创作，新建一个项目。
  2. 点左上角的 导入，选择你的视频（或录屏、PPT 导出的视频），以及生成的音频文件（在 D:\VoiceTwin\workspace\我的声音\outputs 里）。
  3. 把视频拖到下面的时间线上。如果原视频有声音而你不需要，在视频轨道左边点 关闭原声（喇叭图标）。
  4. 把生成的音频拖到视频轨道下方的音频轨道上，对齐开头。
  5. 导入字幕：在顶部的 文本 栏里找到 本地字幕（有的版本叫"导入字幕"），导入同名的 .srt 文件，字幕会自动按时间出现。字幕和音频要从同一个位置开始。
  6. 播放检查。画面和声音对不上时，可以拖动、分割音频片段来调整；也可以在讲稿里加停顿标记重新生成（10.3 节）。
  7. 点右上角 导出，分辨率、帧率按平时习惯设置即可。
剪映的菜单名称会随版本更新而变化，找不到时可以在剪映里搜索"导入字幕"。其它剪辑软件（Premiere、达芬奇、必剪、Camtasia 等）的用法类似：导入音频放到音轨，导入 SRT 字幕。
分段生成更好剪一节课很长时，可以按"小节"分成几份讲稿分别生成，每份对应一段画面，剪辑时更好对齐；改动某一小节也只需要重新生成这一份。

11.3 不用剪辑软件：一条命令替换视频的声音

如果你只想把一个视频的原声音换成生成的音频（例如 10.7 节按字幕重新配音的场景），可以用 mux 命令，几秒钟就完成，画面不会重新压缩，画质不变：

  1. 按 3.7 节的方法，在 D:\VoiceTwin 打开命令提示符。
  2. 输入下面的命令（换成你自己的文件路径），按 Enter： 
    voicetwin.bat mux --video "D:\讲课素材\第1课.mp4" --audio "D:\VoiceTwin\workspace\我的声音\outputs\第1课_10月01日14点19分.wav" -o "D:\成品\第1课_新配音.mp4"
  3. 看到 ✅ 已生成 D:\成品\第1课_新配音.mp4 就完成了。
参数含义
--video原视频文件。
--audio生成的音频文件。
-o输出的新视频文件（所在文件夹要先建好）。
--keep-original（可选）加上它会保留原音轨并和新音频混在一起，适合原视频里有背景音乐、你只想叠加解说的情况。不加就是完全替换。
小窍门：在文件上按住 Shift 点右键，选 复制文件地址（Windows 11 直接右键 → 复制文件地址），再在命令提示符里右键粘贴，就不用手打路径了。路径里有空格或中文时，前后要加英文双引号。

11.4 让声音和画面对齐的技巧

  • 需要等画面时，在讲稿对应位置加 [停顿=秒数]，例如演示操作前加 [停顿=3]。
  • 已有视频要配音时，用字幕时间轴生成（10.7 节），比手动对齐省事得多。
  • 整体长度差一点：用 语速 拉杆微调（−5～+5 之间几乎听不出变化），最多不要超过 −15～+15（9.2 节）。
  • 某一句太长/太短：改写这一句，只重新生成这一句（9.5 节）。

11.5 声音后期处理建议

生成的音频已经是干净的成品：只有你的声音，没有背景音和底噪；句子之间的停顿是完全静音；音量已经自动调到和你原始录音一样。所以一般什么都不用处理，直接用就行。

  • 不需要再降噪、调音量、压缩。觉得声音里有轻微杂音时，用"完美"档的版本 B（去杂音）即可（9.4 节）。
  • 不要加混响、变声、美化效果，会让声音变得不像你；也不需要另外加什么"环境声""底噪"。
  • 生成的音频可以和你的真人录音混在一个视频里使用，两者音量已经接近，生成的音频不需要加任何效果。
  • 如果课程视频里本来就有背景音乐，注意把音乐音量调低（比人声低 15~20 dB，剪映里一般把音乐音量调到 10%~20%），避免盖住讲解。
  • 剪辑时用 WAV 文件最好；导出视频时，音频选 AAC、192kbps 或更高即可。

第 12 章检验效果：评估、鉴别与盲测

"像不像"不能只凭感觉。程序里有三个检验工具：④ 试试像不像（可选） 给任意一段音频打分；⑤ 鉴别 里的机器鉴别一次给很多段音频打分、排名；同一页的观众盲听测试让别人来判断哪段是真人、哪段是生成的。

12.1 用"④ 试试像不像"给一段音频打分

  1. 确认最上面的 声音名称 是"我的声音"。
  2. 点 ④ 试试像不像（可选） 标签页。
  3. 在 音频 框里点 上传 图标（↑），选择要评估的音频文件（wav、mp3 等都可以）；也可以直接把文件拖进框里。想评估刚才生成的音频，不用找文件，点 📥 评估刚才生成的音频，它会自动放进音频框（在 ③ 页面生成完后点 ④ 评估刚才生成的音频 → 也一样）。
  4. （可选）在 对应文字（可选，填了会检查错字） 里填入这段音频说的内容。填了之后程序会把音频识别成文字，和你填的对比，计算错字率和语速。
  5. 点 评估，稍等一会儿，下方显示结果。

12.2 看懂评估结果

项目含义与参考标准
结论（最上面的大字）例如"像你本人 81.1%（有点像）"。100% = 和你自己的真实录音一样像（9.4 节）。95% 以上非常像；85%~95% 比较像；75%~85% 有点像；低于 75% 不太像。低于 85% 就算不够像。
时长（秒）去掉开头结尾静音后的长度。
各声纹模型每个声纹模型分别打的"像你本人（%）"，后面的"原始相似度"（0~1）一般不用看。几个模型的结果差不多时，分数更可信。
语速（音节/秒）（填了文字才有）每秒说多少个字/音节。
你本人的平均语速（填了文字才有）从你的素材里统计出的平均语速。两者越接近，节奏越像你。中文讲课一般在每秒 3.5~5 个字之间。
音高偏差这段音频的平均音高和你本人差多少个"半音"。1 个半音以内基本听不出差别；超过 2 个半音会感觉音调偏高或偏低。
错字率（填了文字才有）识别出的文字和你填的文字有多少不同。5% 以下很好；超过 15% 说明可能有漏读、读错，或者识别模型听错了（专业术语、人名容易被识别错，不一定是真的读错了）。
识别出的文字（填了文字才有）识别模型听到的内容，可以和原文逐字对照，找出读错的地方。
提示发现的问题，例如"语速过快/可能漏读""几乎没有声音"。显示"无"表示没发现问题。
声纹模型这次用来打分的声纹模型。正常是"ERes2NetV2（GPT-SoVITS 自带）"和"Resemblyzer"；如果只写着"简易 MFCC（仅供参考）"，说明没有可靠的声纹模型，百分比只能粗略参考（可以到 🩺 环境检查 看看缺什么）。
分数是参考，耳朵是最终标准相似度是声纹模型自动打分，越高越像，但不是绝对精确。它衡量的主要是"音色"，对语气、节奏、口音不太敏感：90% 的音频也可能某一句语气不对。分数用来快速比较，最终请一定用耳朵听，或者做盲听测试（12.4 节）。

12.3 "⑤ 鉴别"：机器鉴别，一次给很多段打分排名

"④"一次只评一段；⑤ 鉴别 上半部分的 🤖 机器鉴别 可以一次给很多段生成的音频打分，并按"像你本人（%）"排好名次。

  1. 点 ⑤ 鉴别 标签页。
  2. 两个上传框都可以不选：不选时，程序自动用素材里留出的你的真实录音（"考试题"）当标准，鉴别最近一次生成的结果（两个版本和每一句，最多 20 句）。
  3. 想鉴别别的音频，在 要鉴别的生成音频（可选，可多选） 里上传，一次可以选好几个；想用别的真实录音当标准（例如最近新录的几段），在 你的原始录音（可选，可多选） 里上传。
  4. 点橙色的 开始鉴别，等进度条走完。

结果上方写着"🤖 鉴别完成：共 N 个文件，其中 M 个 ≥ 85%"和这次用到的声纹模型。表格各列：

列含义
#编号，从 1 开始。
文件鉴别的是哪个文件。最近一次生成的会写成"版本 A：未去杂音（……）""第 2 句：……"。
各模型 %每个声纹模型分别打的分（括号里是原始相似度）。
综合 %几个模型的平均，就是这个文件"像你本人"的百分比。
排名按综合 % 从高到低排。
是否 ≥85%够不够 85% 的标准：✅ 是 / 🔴 否。

机器鉴别最适合做对比实验：同一段讲稿用不同的方法各生成一次，把几个文件一起上传，看谁排在前面。例如：

想比较什么怎么做
校对前 vs 校对后训练的模型校对前训练一次、生成一段；校对后重新训练、生成同样的讲稿，两个文件一起鉴别。
均衡 vs 完美 档同一讲稿用两个档位各生成一次，一起鉴别。
不同的参考音频在"指定参考音频编号"里填不同的编号生成（13.2 节），比较分数和听感。
不同的引擎用 GPT-SoVITS 和可选引擎（13.4 节）分别生成，比较分数。
你自己的真实录音（作为"满分"参照）把一段没有用来训练的真实录音（例如最近新录的一小段）也放进"要鉴别的生成音频"里，看看你本人能得多少分，作为比较的基准。

12.4 观众盲听测试：让别人来判断

最客观的检验方法是盲测：听的人不知道哪段是真人、哪段是生成的，看他们能不能分辨出来。⑤ 鉴别 下半部分的 👂 观众盲听测试 会帮你把题目做好：电脑从你没参加训练的真实录音里挑几句，再用你的模型读同样的句子，统一音量、打乱顺序、编上号。

  1. 在 用几句话（真人和生成的各这么多段） 里选数量，例如 10（就是真人 10 段 + 生成 10 段，一共 20 段）。
  2. 点 生成盲听测试，等进度条走完（会用到显卡，大约几分钟）。生成用的是 ③ 页面当前选的质量档位。
  3. 页面上出现"第 1 段""第 2 段"……每段一个播放器，旁边是 真人 / 生成 两个选项（图 12-3）。
  4. 请听众（同事、学生，最好是熟悉你声音的人）逐段听，每段选"真人"或"生成"。不要告诉他们各有几段。
  5. 全部选完后点 提交答案（每段都选了才能提交），程序马上批改：显示答了几段、答对几段、正确率，以及每段的正确答案。答案在提交之前不会显示，提交后选项会锁住，不能再改。

离线测试：把题目发给别人，收回答题卡再批改

  1. 生成盲听测试后，页面上写着题目文件夹的位置，例如 ……\outputs\盲听测试_20261001_142739。里面是编好号的录音（01.wav、02.wav……）和一份 听众答题卡.txt。把整个文件夹发给听众。
  2. 答案不在这个文件夹里，而是在它旁边的"……_答案（只给老师看，不要发给听众）.json"，不要一起发。
  3. 听众在答题卡上每段写"真人"或"生成"，交回给你。
  4. 回到 ⑤ 鉴别，点开 📝 批改收上来的答题卡（离线测试、网页刷新过也能用），在 选一次盲听测试 里选这次测试，把答案填进 听众的答案（可以写 1 真人 2 生成 3 真人 ……，也可以不写编号、按顺序写 真人 生成 真人 ……），点 📝 批改。

有几位听众就分别批改几次，再把正确率平均一下，按下表判断：

平均正确率说明
≤ 60%和瞎猜（50%）差不多，基本听不出区别。效果非常好。
60%~80%有时能听出来。看看哪几段最容易被听出来，问问听众是怎么判断的（"这句语气怪""这个字读得不对"），针对性改进，例如用"完美"档重新生成那几句。
> 80%比较容易分辨。按 12.5 节和第 13 章的方法改进：增加素材、校对文字、用"完美"档等。
题目太少（少于 6 段）时，结果只能参考，程序也会这样提示。正确率只说明"这几位听众、这几句话"的情况，换了内容、换了听众，结果会有不同。

12.5 客观看待效果：哪些地方最容易露馅

根据经验，下面这些情况最容易让人听出是生成的，写讲稿和挑选句子时可以留意：

容易露馅的地方改进方法
很长的句子，后半句语调越来越平拆成短句（10.8 节）。
强烈的情绪（大笑、激动、生气）模型主要学会了你讲课时的状态，强烈情绪很难模仿。讲稿里尽量避免，或者这几句用真人录音。
笑声、咳嗽、清嗓子、"嗯……"等无法生成，不要写在讲稿里。
专业术语、人名、多音字读错用读音词典纠正（10.4 节）。
停顿太规律程序按你的习惯决定停顿长短，每次略有变化；也可以手动加一些 [停顿=…] 让节奏有变化。
停顿处特别安静这是特意这样做的：成品里只要你的声音，停顿是完全静音。单独放在课程视频里一般不明显；但和带环境声的真人录音紧挨着仔细对比时，有可能被听出来。不需要另外加任何声音（11.5 节）。
英文带中文腔增加你讲英文的素材（4.3 节）后重新训练。
个别句子有杂音、电流声、吞字只重新生成这几句（9.5 节）；最好、极致、完美档会自动检查和重做；"完美"档还可以选去杂音的版本 B。
任何声音克隆技术都做不到 100% 无法分辨。本程序的目标是：在正常讲课内容上，让大多数听众注意不到是生成的。关于公开使用时是否需要说明，请看附录 D。
