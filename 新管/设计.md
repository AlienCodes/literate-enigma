# 新管落地设计（精简第八棒，2026-10-28）

## 核心
一份数据（genNN → scripts/NN.json）、一条命令（做.sh / 定稿.sh）、一张规则表（规则表.json）、一个快测（快测.py）。
检查代码一行不重写：规则表里每条规矩指向现有检查程序 / 函数；自检里造的坏样本 = 规则的坏样本。

## 规则怎么搬（机器搬，不手抄）
1. 规则执行表 每条已有 门[程序,原文] 与 自检[程序,原文]：门在 踩坑核查/译文核查/check_all/说明分行… → 文本；在 交付核查出片前、读音核对、标点停顿… → 合成前声音；交付核查出片后、audio_qc、机器复听、响度、纯人声、高亮、独立复核 → 出片后；make_video/render（出片守门自检覆盖）→ 出片内；推送/定稿流水线/归档 → 定稿；钩子/规则执行核查/门变异/证据/用上/丝滑/演练/放行口子/会话开工/开工必读/方法进化 → 看门（替代）。
2. 程序归不进任何一类的规则 → “没搬”清单，逐条写原因；验收要求为 0 或有原因。
3. 级别：程序现有输出分 BAD/停止 → 错；“待用户判/需试听/人看” → 疑；有 --写入 的 → 修。

## 快测怎么跑
- 自检清单 = 规则表里所有 自检 的程序去重（约 25 个 --自检 + 踩坑核查 selftest_* + 出片守门自检），进程池并行。
- 27 回归：快速重建（配音缓存命中，不调模型）→ 比 a.wav/分段.json md5；render 抽每屏一帧比哈希（不编码整片）。
- 改规则的门槛：快测过 → 可推。全量门变异降为每周后台体检（不拦人）。

## 预计
- ② 规则表+快测：约 40 次调用、1.5 h；③ 做.sh/定稿.sh：约 40 次、1.5 h；④ 须知/一页版/原话：约 20 次、0.7 h；⑤ 27 验收（含搭环境、出 4K）：约 30 次、1.5 h。
- 合计约 130 次调用、5–6 小时、约 10–13M 等效 token（单会话，不派子代理）。
- 风险：本容器没有 P 仓库、模型要下载（准备机器.sh）；27 回归逐字节依赖缓存全在仓库。先 10 分钟内试搭环境，搭不起来立刻报。
