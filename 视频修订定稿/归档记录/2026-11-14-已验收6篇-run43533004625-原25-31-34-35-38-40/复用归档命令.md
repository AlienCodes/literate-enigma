# 连续归档已实际通过的单篇或批次

复用已完成的两片归档流程，输入preflight实际V3 passed handoff。程序保存原字节与原provenance，不制作视频，也不改原核查器。原请求、实际工作JSON、最终GEN和MD的来源标签原样保留；派生GEN不能写成运行时观察值。

同一程序用于单篇及articles数组中的多篇：

```
python archive_batch.py prepare --handoff HANDOFF.json --work-dir WORK --batch 唯一批次目录名
python archive_batch.py push --work-dir WORK --repo alienalgorithm/postgraduate-vocabulary
python archive_batch.py push --work-dir WORK --repo AlienCodes/literate-enigma
python archive_batch.py stream --work-dir WORK
python archive_batch.py index --work-dir WORK --existing 当前累计清单.json
```

首次累计清单可从已经永久保存且核验过的书序35、63两篇原回执建立；之后读取主仓当前`视频修订定稿/已归档视频总清单.json`合并本批。按原ID去重，旧版不同SHA保留在previous_versions中，不能累计同篇为两篇。总清单按书序排列，未完成的篇目不能算已验收，不能由样本宣布70部全部完成。

push仅写独立assets分支，并将大批素材分为约64MiB的原始Git资产增量推送。prepare/index/stream不更改主干。集成时读取主main和backup专用分支的最新HEAD，用Git Database仅添加该批冻结子树、相邻操作记录和累计清单；新commit以刚读的HEAD为唯一parent，update_ref使用expected_sha且force=false。若HEAD改变，读取新HEAD后基于新树重新合并。backup master保持。

大仓库的backup已实际遇到`base_tree`加深路径编辑超时422。后续直接读取各层的即时条目，先合并小的“归档记录”树，再合并“视频修订定稿”树，最后仅替换根树中的该目录链接；三个create_tree均不传巨型base_tree。原其他条目全部保留，新视频目录树SHA应与主仓相同，再以当前HEAD为parent更新分支。47篇已经用这条小树路径恢复成功。

集成后读回路径、blob SHA、字节数、全目录树及branch ref，并核实旧批次与印刷637件冻结树未变。MP4以两仓实际HTTPS字节流核SHA，不另外落重复视频。临时bare对象可在远端恢复验证后删除，视频原件、原始ZIP、文稿、程序、QA与回执保留。

每批保存到独立新目录，旧两篇目录不覆盖。最终Release仍等待70篇全部真实验收，只含整本PDF和70部4K，不在部分批次建立Release。
